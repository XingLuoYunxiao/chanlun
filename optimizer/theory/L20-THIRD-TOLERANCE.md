# 第三类买卖点：位置判据、必须是第一次、容忍度（第 20、24、32、33 课）

## 原文摘录

第 020 课《缠中说禅走势中枢级别扩张及第三类买卖点》：

> 由定理一，可以得到第三类买卖点定理：一个次级别走势类型向上离开缠中说禅走势中枢，
> 然后以一个次级别走势类型回试，其低点不跌破ZG，则构成第三类买点；
> 一个次级别走势类型向下离开缠中说禅走势中枢，然后以一个次级别走势类型回抽，
> 其高点不升破ZD，则构成第三类卖点。

第 020 课：

> 但一定要注意，并不是任何回调回抽都是第三类买卖点，必须是第一次。

第 020 课中心定理一：

> 走势中枢的延伸等价于任意区间[dn，gn]与[ZD，ZG]有重叠。

第 024 课：

> 其后的次级别回跌并不重新回到前面的中枢里

第 032 课：

> 如果一个5分钟级别的回拉不回到中枢里，就意味着有第三类买点

第 033 课：

> 次级别回抽一旦不重新回到中枢里，就意味着第三类买点出现了

## 判据一：「必须是第一次」现行代码**已经满足**，不需要补过滤

`src/chanlun/chan/pivot.py` 的 `find_pivots` 延伸循环
`while j < n and j - i < MAX_SEGMENTS and _overlaps(confirmed[j], zd, zg)`
让中枢**在第一个完全不碰 `[zd, zg]` 的段处封闭**，`end_idx = positions[j-1]`。
因此 `src/chanlun/chan/signal.py` 的 `_third_kind` 唯一取用的回试段
`segs[p.end_idx + 1]` **就是**离开中枢后的第一次回抽（转述），结构上不可能取到第二次。
`find_pivots` 里紧跟的 `i = j` 又保证相邻中枢的 `end_idx` 严格递增，
同一次离开不会重复产出。

**已作废的度量**：曾统计中枢组内部在最后一段之前是否已有段越过 ZG（转述），
40 只票 / 64 个第三类信号命中 50 个（78%），一度判为偏离。
但这是**中枢延伸的正常形态** —— 由中心定理一，组内同向段只要 `dn <= ZG`
就仍在延伸，`gn` 完全可以远高于 ZG（实测 `600537` 的 ZG=5.4、组内某段最高 8.79）。
该指标测量不到「第一次」这件事。

## 判据二：容忍度 = 原文空白项，属工程口径 ⇒ **2026-10-04 已整体移除**

四课原文一致使用「不跌破」「不重新回到」「不回到」，
**没有任何允许小幅回到中枢的措辞**。
⇒ 容忍度 `tol` 无原文依据，只能在非严格模式生效，
且必须在代码注释、本条目、UI 文案三处标注为**工程口径**。

**2026-10-04（D-41）：`THIRD_TOL` 已从 `signal.py` 删除，`SignalMode.LOOSE` 不再放宽第三类判据。**
理由不是「工程口径不好」，而是它**赖以存在的机制被实测证伪**（见下方判据三的更正），
且它实际翻出来的信号与第 20 课的判据**正面冲突**：

- 容忍度的判据是 `back.low > p.zg - tol`（卖点侧对称），也就是**允许回试段跌回 `[ZD, ZG]` 之内**；
- 第 20 课原文是「其低点**不跌破** ZG」「但一定要注意，并不是任何回调回抽都是第三类买卖点，
  **必须是第一次**」，第 24/32/33 课一致「**不重新回到**中枢里」；
- 容忍度翻出来的信号里，**55 条（全市场日线）挂在中枢还没封口的尾段上**
  （`Pivot.status is TENTATIVE`，回试段就是最后那一段、且与 `[ZD, ZG]` 重叠），
  这些信号在任何口径下都不满足原文。

⇒ 现在 `严格` 与 `非严格` 在**第三类买卖点上完全同判**（全市场日线实测 `b3 3065 / s3 2723`，两口径逐项相同）。
非严格模式剩下的差别只有两处，都不涉及第三类：盘整背驰另算买卖点（`pb`/`ps`，第 27/39 课口径）
与第二类不要求前置第一类（D-33）。

## 判据三：容忍度的作用面（**2026-10-04 更正 —— 原判据已被实测证伪**）

> **原判据三（保留原样，作为「当时为什么那样写」的记录）**：
> 容忍度只可能在**被段数上限截断**的中枢上翻结论。
> 下面这一段推理**本身没错**（对**已确认**中枢而言它是对的），
> 但它把「中枢组没满 8 段」等同于「回试段一定被并进中枢组」——
> **漏了延伸循环撞到列表末尾的那条路径**（`j == n`），
> 于是漏掉了一整类信号。更正见本节末尾的「**更正**」。
>
> **证伪它的实测（全市场日线 5440 票，2026-10-04）**：非严格模式独有的第三类信号
> **99 条**（`b3 45 / s3 54`），分类后是
> **44 条「已确认 + `capped`」+ 0 条「已确认 + 非 `capped`」+ 55 条「中枢未确认」**。
> 也就是说：**在已确认中枢上原判据成立（44/44，反例 0 条）**；
> 但它**不完整** —— 还有 55 条落在**尚未封口的中枢**上，原判据一个字都没提到。
> 分类探针与输出见 `docs/evidence/2026-10-04-capped-signal-gate.md`。

`find_pivots` 的延伸循环会把**任何**仍与 `[zd, zg]` 重叠的后续段并进中枢组
（`_overlaps` 是闭区间 `seg.low <= zg and seg.high >= zd`），
只有 `MAX_SEGMENTS = 8` 先到，回试段才会「重叠却没被并进去」：

- 中枢组没满 8 段：回试段一旦回到 `[zd, zg]` 里就被并进中枢组，`end_idx` 后移，
  `_third_kind` 取到的「回试段」随之变成更后面那一段 —— 穿透型回试**根本不会**
  作为第三类候选出现，`tol` 取多大都翻不了结论；
- 中枢组已满 8 段：截断把回试段留在组外，`back.low` 落在 `(zg - tol, zg]` 时
  严格模式不出、非严格模式出。

```python
import random
from pathlib import Path
import pandas as pd
from chanlun.chan.engine import ChanEngine
from chanlun.chan.signal import SignalMode, _third_kind, find_signals

pool = []
for pref in ("sh", "sz"):                        # bj 目录 0 个文件
    for f in sorted(Path("data/day", pref).glob("*.parquet")):
        df = pd.read_parquet(f)
        if len(df) >= 250:                       # 池子共 5327 只
            pool.append((f"{pref}.{f.stem}", df.drop(columns=["code"], errors="ignore")))
pool.sort(key=lambda x: x[0])
random.seed(7)
n_s = n_l = diff = 0
for code, bars in random.sample(pool, 60):       # 抽 60 只
    snap = ChanEngine(code, "day", signal_fn=find_signals, level="day").full(bars)
    segs, pivs = list(snap.segments), list(snap.pivots)
    s = _third_kind(segs, pivs, "day", SignalMode.STRICT)
    l = _third_kind(segs, pivs, "day", SignalMode.LOOSE)
    n_s, n_l = n_s + len(s), n_l + len(l)
    if len(s) != len(l):
        diff += 1
        for x in l:
            p = next(q for q in pivs if q.idx == x.pivot_idx)
            back = segs[p.end_idx + 1]
            over = (p.zg - back.low) / (p.zg - p.zd)
            print(f"{code} {x.kind.value} {x.ts} 越界比例={over:.4f} "
                  f"中枢段数={p.segment_count} 中枢高度={p.zg - p.zd:.3f}")
print(f"第三类：严格 {n_s} / 非严格 {n_l}；计数不同的票 {diff}/60")
```

### 更正（2026-10-04，D-41）：漏掉了「延伸循环撞到列表末尾」这条路径

上面那段 60 票的抽样只逮到 **1** 个被容忍度救回的信号，于是当时的结论是
「第三类计数不同的票只有 1/60 ≈ 1.7%，容忍度影响面极小」。**换到全市场 5440 票，
这个数字是 99 条**（`b3 45 / s3 54`）—— 抽样把结论带偏了一个数量级。

分类这 99 条（探针 `/tmp/probe_n2_class.py` 的等价实现，见
`docs/evidence/2026-10-04-capped-signal-gate.md`）：

| 类别 | 条数 | 中枢 | 回试段 | 与 `[ZD, ZG]` 重叠 |
|---|---|---|---|---|
| A 已确认 + `capped` | **44** | `status = CONFIRMED`、`capped = True` | `CONFIRMED` | `True` |
| B 已确认 + 非 `capped` | **0** | `status = CONFIRMED`、`capped = False` | — | — |
| C 中枢未确认 | **55** | `status = TENTATIVE` | `TENTATIVE`（就是最后一段） | `True` |

- **B 类为 0 ⇒ 原判据在已确认中枢上是对的**，而且有结构性理由：
  已确认且非 `capped` 的中枢满足 `j < n and not _overlaps(confirmed[j], zd, zg)`，
  回试段必然整段在枢外，`back.low > p.zg` 直接成立，`tol` 用不上。
- **C 类是原判据完全没覆盖的生成器**：延伸循环因为 `j == n`（列表到末尾）而停下，
  `capped` 判据里的 `j < n` 不成立 ⇒ `capped = False`，但**最后一段仍与 `[ZD, ZG]` 重叠**、
  且它本身是 `TENTATIVE`。`_third_kind` 把它当回试段，`tol` 一放宽就出信号 ——
  而第 20 课要求的是「回试」之后**不再回到**中枢里，尾段还在枢内时中枢根本还没封口。
- 所以 44 条是「`capped` 的收口没做到信号层」（N-1），55 条是「未封口中枢出了第三类」
  这个**独立的**候选缺陷。**D-41 只收口了前者**：`_third_kind` 现在要求
  `p.capped is False`。后者（再加一道 `p.status is Status.CONFIRMED`）**经用户裁决
  暂不采纳**，理由与实测边际量见 D-41 的「被否决的替代方案」；那条判据仍留在待评审盘上
  （`optimizer/patches/round-006-G3a.patch`，已按删掉 `THIRD_TOL` 后的主干第四次重锚）。

## 被否决的替代方案

- **把容忍度写进严格模式**：违反第 20/24/32/33 课，否决。
- **保留容忍度、只把「未封口中枢」收口**（2026-10-04 重新评估后否决）：
  这是 D-41 的第一版方案 —— 只加 `p.status is CONFIRMED`，不动 `THIRD_TOL`。
  实测它会把非严格独有的第三类从 99 条降到 **55 条**，但那 55 条**全部**是
  「回试段跌回 `[ZD, ZG]` 之内」的信号（A 类已被 `capped` 收口），
  与第 20 课「其低点不跌破 ZG」正面冲突。容忍度原本的辩护是「补偿 `capped` 截断」，
  `capped` 一旦收口，这个辩护就消失了 ⇒ 一并删除。
- **用中枢延伸后允许后续回抽来放宽「必须是第一次」**：实测为空操作
  （见判据一）。唯一例外是被 `MAX_SEGMENTS = 8` 截断的中枢 —— 那里的回试段
  本该被并进中枢组，容忍度确实会翻结论；但那是「容忍度」这一条（判据三），
  不是「第二次回抽」的放宽，不能拿它给「必须是第一次」开后门。
- **把严格判据改成 `>=`（贴合「不跌破」的字面）**：字面上「其低点不跌破ZG」
  含等号，现行代码是 `back.low > p.zg`，即比原文更严一点点。但严格模式有
  「与 Task 5 提交逐字节一致」的硬约束（R1 裁决 G），改代码会动到已有信号，
  故本轮只把文档从 `>=` 更正为代码实际的 `>`，等号归属记为**已知偏差**，
  留待将来单独论证（D-35 变更历史）。
