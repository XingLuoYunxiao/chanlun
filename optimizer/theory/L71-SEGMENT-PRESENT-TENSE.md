## 原文摘录

第 071 课《线段划分标准的再分辨》：

> 其实，线段的划分，都是可以当下完成的，无非是如下的程序：假设某转折点是两线段的
> 分界点，然后对此用线段划分的两种情况去考察是否满足，如果满足其中一种，那么这点
> 就是真正的线段的分界点；如果不满足，那就不是，原来的线段依然延续，就这么简单。

配套的两段（第 78 / 79 课）是判据的另外半边：

第 078 课《继续说线段的划分》讲第二种情况时说明，第二个分型**可以远在后面**才出现
—— 所以「确认元素在后面」本身不违规。

第 079 课《继续说线段的划分》讲第二种情况的确认时给出逐字实例：

> …34、56、78，**其中前两者可以进行包含关系处理，因此可以合并为36（指区间）**…

—— **包含处理先于分型**。这是「先合并、再看分型」这个顺序的原文依据。

## 释义

原文把线段划分定义成一个**逐转折点的假设-验证程序**：
「假设某转折点是分界点 → 用两种情况考察 → 满足则定，不满足则原线段延续」。
它有两个本项目必须分开对待的性质：

1. **性质 1 · 单调向前**：已经定下的分界点不被后来的 bar 改写。
2. **性质 2 · 结论「当下」可得**：原文说「都是可以当下完成的」，所以一个分界点
   成不成立，只能由**它之前（含它）已经出现的笔**决定。

**性质 2 不等于「确认必须立刻发生」。** 把第 71 课和第 78 课放在一起读，得到的是
一条很具体的可计算性约束：

> 向未来**等待**可以，向未来**借用**不可以。

第二种情况的分型本来就允许出现在很后面（第 78 课），所以「确认元素在后面」是合法的；
违规的是把**前缀之后**的元素拿来当成**前缀内**候选的证据 —— 那等于让今天的划分
依赖于明天才知道的事，正是「当下完成」要排除的东西。

主干原先有两处踩了这条线，见下。

## 两个根因（都是「向后借用数据」）

### (a) 缺口确认前视 —— `_confirm_gap`

旧实现的做法是：把 `from_idx` 之后的**全部**笔取出来、合并成特征序列，然后在里面
找分型，返回分型**下一个**元素的笔号。问题是这个「下一个元素」可能落在
**当前前缀之外**。

可复现的反例（`sh.000001`，`start=62`，`direction=1`，候选 `k=2`，`end_idx=66`）：

```
n=79 笔（k=890）：std = [(72), (74), (76), (78)]  → 命中 j=2，确认元素 = std[3] = 笔78
                                                     ⇒ 候选 66 成立
n=82 笔（k=930）：std = [(72), (74), (80)]        → 无命中 ⇒ 返回 None
                                                     ⇒ 候选 66 被删掉
```

也就是说：**在只有 79 根笔的时候，系统用第 78 笔（前缀内）宣布了 66 这个分界点；
等到有 82 根笔时，第 78 笔已经被合并掉了，66 又消失。** 依据是第 79 课
「前两者可以合并」——合并关系会随新笔到来而改变，所以旧实现是在用**未来的合并结果**
去确认**过去的**分界点。

修法：按笔**逐根推进**，只用已经走完的笔判定分型（先合并、再看分型），
第一个满足就返回。这样「第 78 笔」在 n=79 时是真实存在的证据，n=82 时它已经
被合并进区间 36，两个时点的答案各自在自己的前缀内成立，不再互相否定。

### (b) 左端起段漂移 —— 窗口左端

旧实现按**全序列 argmax** 选窗口起点：把所有起点都试一遍，取「使线段总数最大」的
那一个。数据一多，最优起点就往前跳：

```
sh.601012   k=250 笔 → 起点 = 第 13 笔
            k=330 笔 → 起点 = 第 1 笔
```

这是**结构性**非因果：`k=250` 时看到的划分和 `k=330` 时看到的划分，起点都不一样，
所以前缀之间的对比根本不是同一件事。

修法：**取最早的前缀上第一个可行的起点** —— 只要前缀上存在可行起点就停，
不做全序列比较。注意「第一个可行」必须是**因果**版本：全序列版的「第一个可行起点」
实测是 7582 / 58 / 15 / 43，比因果版（7787 / 52 / 14）更差。

## 决策：改为主干前缀因果（D-40）

本轮**真的改了主干判据**，把两处「向后借用」都改掉：

1. `_confirm_gap` → 逐笔推进、只用已走完的笔（因果确认）。
2. 窗口左端 → 取最早前缀上第一个可行的起点（因果起点）。

效果：**违规 20 → 14（−30%）**，累计确认 **7855 → 7787（−0.9%）**，结构未塌陷。
残留 14 条如实记录（M6）。

**仍然没有做到 0。** 真正的 0 需要跨次调用锁定已宣布的分界点（有状态）：
`classify(strokes)` 目前是无状态的，锁定需要 `ChanEngine` 承载已确认分界点列表，
并改动 `full()` / `step()` 的契约，还会重新锚定全系统所有冻结数字。这是 D-39 的
已知空白，**本轮依然保留**。

**被否决的替代方案**（完整表见 ARCHITECTURE.md D-40）：

- 「起点固定第 0 笔」（L1）：违规 5 是塌结构换来的（`sh.000001` 最长 37 → 376）。
- 「第 71 课字面程序」（F2）：20 → 28，更差。
- 「已宣布即永久」（P4）：违规 0，但 `pytest` **36 failed / 917 passed**。
- 「平局取更早确认的候选」：7787 / 46 / **11** / 35，比 14 更好，但**原文没有依据**，
  且把划分与确认机制耦合起来 —— 未采纳（实测来自临时探针，命令未入库）。
- 廉价代理规则（minconf / maxconf / `closed_only` / `closed_candidates` / O3）：
  要么回归、要么崩结构。
