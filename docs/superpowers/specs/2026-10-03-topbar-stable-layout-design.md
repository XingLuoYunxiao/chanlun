## 1. 背景与目标

### 1.1 用户诉求（原话）

> 「我发现一个简单的问题，就是在看月线、周线、日线这一块切换的时候，它这个UI总是会进行一个自适应变动。我感觉看起来很不舒服，意思就是能不能把它切改成那种固定格式的，然后只要不遮挡这个文字，看起来比较舒适就行。就是那一行，我不知道是那一行的问题，还是只是他们的这几个按钮的问题。」

拆成三条可验收的需求：

| # | 需求 | 验收方式 |
|---|---|---|
| R1 | 切 日线 / 周线 / 月线 时，顶栏那一行**不再自适应变动** | 真实浏览器实测各周期下的盒模型尺寸 |
| R2 | **不遮挡文字**（不许截断、裁切、省略） | 检查 `scrollWidth == clientWidth`，且文案可读 |
| R3 | 切 严格 / 非严格 口径时同样稳定 | 同上，两种模式都测 |

### 1.2 用户自己的疑问

用户问「是那一行的问题，还是只是他们的这几个按钮的问题」。

**答案是两者都是，且以那一行为主。** 见 §2。

## 2. 诊断（实测，非推测）

工具：headless Chrome 154 + CDP（`Emulation.setDeviceMetricsOverride`），真实服务端数据
（`sh.000001`，`limit` 默认），窗口高度固定 1000。

### 2.1 现状：按钮折行的临界宽度是 1440px，不是 1600px

严格口径下，只改视口宽（周期固定 `day`）：

| 视口宽 | `.period` 按钮 | `.periods` 宽 | `.query` 宽 | `.stamp` 宽 | `.topbar` 高 |
|---|---|---|---|---|---|
| 1600 | **59.8 × 36** | 298.6 | 648.5 | 696.6 | 93 |
| **1440** | **44.4 × 56** | 209.4 | 537.5 | 656.7 | 110 |
| 1366 | 44.4 × 56 | 209.4 | 537.5 | 596.5 | 110 |
| 1280 | 44.4 × 56 | 209.4 | 537.5 | 526.4 | 110 |
| 1200 | 44.4 × 56 | 209.4 | 537.5 | 461.3 | 110 |
| 1024 | 44.4 × 56 | 209.4 | 537.5 | 318.0 | 144 |
| 900 | 44.4 × 56 | 209.4 | 537.5 | 217.0 | 192 |
| 800 | 44.4 × 56 | 209.4 | 537.5 | 117.8 | 311 |

**只要窗口不超过 1440px，按钮就一直折成两行**（高 36 → 56px）。

### 2.2 非严格口径把临界宽度推到 1600px 以上

`app.js:123` 把口径存进 `localStorage`（`readChoice(LS_MODE, MODE_ORDER, "strict")`），
所以口径是**粘性**的。非严格模式下那段 102 字的口径说明（`app.js:257`）把 `.stamp`
撑到 **850px**，实测在 **1600px 就已经折行**：

| 视口 1600 | 按钮 | `.topbar` 高 |
|---|---|---|
| 严格 | 59.8 × 36 | 93 |
| 非严格 | 44.4 × 56 | 110 |

⇒ 抖动的严重程度取决于用户上次选的口径。

### 2.3 三个独立的变动源

1. **`.stamp` 宽度**：696.6 → 850px。周期加「由日线聚合」、口径换文案都会改它。
2. **`.stamp` 行数**：3 → 4 行。「全史」那行（`app.js:234-236`）只在窗口数 ≠ 全史数时出现。
3. **后果**：`.query` 被挤压 → `.period` 折行（36 → 56px）→ `.topbar` 高 83 → 110px。

### 2.4 根因

`styles.css:103` `.periods` 自身没有 flex 规则，子元素 `.period` 是 `flex: 0 1 auto`
（计算值），而 `.stamp` 的宽度**完全由文字内容决定、没有任何约束**。
`flex: 0 1 auto` 允许按钮缩到内容宽度以下，`overflow: hidden` 再把多出来的部分裁掉。

**按钮是无辜的**：它是被 `.stamp` 抢走空间后的受害者。
`.brand`（158.9px）与 `.query` 左边缘（206.9px）在所有状态下都是固定的。

## 3. 被否决的方案

### 3.1 方案乙：原地预留固定尺寸

内容位置不变，给 `.stamp` 固定宽度 + 固定高度（按最坏 110px 预留），按钮 `flex: none`。

**否决理由**：顶栏常年按最坏情况偏高，严格口径下右侧长期空一块；且 102 字文案塞进
固定宽度后会折成 2–3 行，可读性反而变差。

### 3.2 方案丙：只冻结按钮 + 单行截断

每行 `white-space: nowrap` + `text-overflow: ellipsis`。

**否决理由**：绝对恒定，但窄窗口会截断文字 —— 直接违反 R2。

### 3.3 朴素修法：只加 `.stamp { flex: none }`

**这是实测否决的**，不是推测。注入 `.period{flex:none;white-space:nowrap}` +
`.stamp{flex:none}` 后：

| 视口宽 | 按钮 | `.periods` 宽 | `.stamp` 宽 | 文档需 | 溢出 |
|---|---|---|---|---|---|
| 1600 | 59.8 × 36 | 298.6 | 696.6 | 1600 | 否 |
| 1440 | 59.8 × 36 | **270.7** | 696.6 | 1440 | 否 |
| 1366 | 59.8 × 36 | 270.7 | 696.6 | **1430** | **是** |
| 1280 | 59.8 × 36 | 270.7 | 696.6 | **1430** | **是** |
| ≤1366 | 59.8 × 36 | 270.7 | 696.6 | **1430** | **是** |

两个问题：① `.stamp` 不再收缩 ⇒ **≤1366px 出现横向滚动条**（治抖动换来横向滚动）；
② `.periods` 被压到 270.7 < 按钮总和 298.6 ⇒ `overflow: hidden` **裁掉约 26px**，
最后一个「5分」按钮被切边 —— 违反 R2。

## 4. 设计

### 4.1 内容拆分：顶栏只留恒定 2 行

`app.js:237-241` 现在一次性写 4 行。拆成两处写入，**文案一字不改、一字不丢**。

**顶栏 `.stamp`（恒定 2 行，就是现在的第 1、2 行）**

```
sh.000001 上证指数 · 日线 · 截至 2026-09-30
线段 10（确认 9 / 未确认 1） · 中枢 2 · 买卖点 0
```

**新增 `#stamp-detail`（顶栏正下方、`.disclaimer` 上方，全宽）—— 恒定 2 行**

```
全史 80 段 / 13 中枢 / 6 买卖点（这里只画与窗口相交的部分） · 周线由日线聚合
第一类买卖点取自趋势背驰；趋势按 [DD,GG] 波动区间判（第20课中心定理二；GG/DD 不含离开段，不是中枢区间 [ZD,ZG]）
```

- **第一行** = 全史计数 + 周期来源。窗口 = 全史时（月线）全史计数是空串，
  但**空串也要占一个行盒**，否则月线比日/周线少一行。
- **第二行** = 口径，且**只有口径**。

> **实现中修正的一处设计缺陷**：§4.1 初稿把「周期来源」留在**第二行**
> （`周线由日线聚合 · <口径>`）。实测 800px 严格模式下日线 2 行、周/月 3 行 ——
> 前缀让口径多折一行，详情行差 17px，图表照跳。
> 把周期来源挪进第一行后，第二行在任何周期下**逐字相同** ⇒ 折行数相同 ⇒ 高度相同。

严格口径那一句就是 `app.js:54` 的 `TREND_BASIS` 逐字全文（68 字）；
非严格那一句是 `app.js:261` 的 102 字长文案。两句都**原样搬移，不改一字**：
全文的字符与顺序都没变，只有换行位置移动（「周线由日线聚合」与 `\n` 交换了位置，
` · ` 从第二行挪到第一行）。

之所以搬走口径而不是别的：口径说明**严格 68 字 / 非严格 102 字**，
是宽度与行数的最大变量；周期来源也是周期性变量。两者都必须在顶栏之外。

### 4.2 CSS（下面是**实现后**的真实内容）

```css
.period  { flex: none; white-space: nowrap; padding: 8px 14px; }  /* 按钮永不被压缩折行 */
.periods { flex: none; overflow: hidden; }                        /* 按钮条永不被裁切 */
.stamp   { flex: 1 1 auto; min-width: 0; }   /* 挤压力转给图注自己折行，而非抢按钮空间 */
.stamp-detail {                              /* 顶栏之外，全宽独立一行 */
  padding: 0 20px 8px; font-family: var(--mono); font-size: 12px;
  white-space: pre-line;                     /* 保留 \n，其余空白折叠 */
  line-height: 17px;   /* ★ 必须写死，理由见 §4.4 */
  min-height: 42px;    /* = 17×2 + 8 padding（`* { box-sizing: border-box }`） */
}

@media (max-width: 860px) {                  /* 补上 760–810px 的溢出缝 */
  .topbar { flex-wrap: wrap; row-gap: 10px; }
  .stamp  { flex: 1 1 100%; width: 100%; text-align: left; }
}
```

`.stamp { flex: 1 1 auto; min-width: 0 }` 是关键：**不冻结它，而是让它在自己盒子里折行**，
所以永远不会横向溢出；同时 `.period` 已经 `flex: none`，按钮不再被牵连。

### 4.3 窄屏断点 860px 的由来

顶栏最小需求 = 40（padding）+ 56（gap）+ 158.9（brand）+ 555（`.query` 的 min-content）
≈ **810px**。既有断点在 760px（`styles.css:611-613`），中间 760–810px 会溢出。
860px 留出余量。该断点只作用于 `.topbar` / `.stamp`，**不触碰 `.work` / `.rail` 的既有 760px 断点**。

### 4.4 两处「必须写死」的东西，都是实测逼出来的

**其一：`line-height: 17px`。** 初稿只写 `min-height: 36px`，留给 `normal`。
实测月线详情行比日/周线矮 3px（`42/42/39`）：月线第一行是**空**的，
而空行的行盒只按字体 strut 算，比含中文的行矮。写死 `line-height` 后每个行盒一样高，
`min-height` 也改成 2 行的真实盒高 42px。

**其二：`min-height` 而不是 `height`。** 窄屏下口径会折成 2 行，`height` 会把文字裁掉 ——
用户明确要求「只要不遮挡这个文字」。所以是**预留**：内容超过 2 行时盒子跟着长，
下方图表会下移一点（实测 1024px 及以下非严格口径 59px，严格 42px），
但**同一宽度下三个周期完全一致**，周期切换不再引起跳动。

> 备选：把「全史」行改成始终显示即可消除第一行空串，但会在窗口=全史时印出一句
> 语义可疑的话（「这里只画与窗口相交的部分」此时是废话）。**选了留空行，不发明文案。**

### 5.2 复测之前先踩了三个坑（都靠这一测量才发现）

| 轮次 | 测到 | 根因 | 修法 |
|---|---|---|---|
| 第 1 轮 | 详情行高 `42 / 42 / 36` | 月线没有「全史」行 ⇒ 少一个行盒 | 空串也占一行 |
| 第 2 轮 | `42 / 42 / 39` | 空行的行盒只按字体 strut 算，比含中文的行矮 3px | `line-height: 17px` 写死 |
| 第 3 轮 | 800px 严格 `42 / 59 / 59` | 周期来源前缀让口径多折一行 | 周期来源挪进第一行 |

三轮都是**只有这一测量能看见**的缺陷 —— 布局上看不出来（截图会骗人），
逻辑行数上也不违反契约。若不做这次复测，会把「42/42/36」当成通过。

### 5.3 反面对照（测量必须能失败）

朴素修法（只加 `.period { flex: none }` + `.stamp { flex: none }`，见 §3.3）
在 1366px 及以下**横向溢出**（文档宽 1430px）、`.periods` 被压到 270.7px、
最后一个按钮被裁掉。同一个探针能测出「溢出 是 / 裁切 有」——
说明这组指标不是恒满分。

  真实浏览器这两档未量，不许把模拟数字当实测。
