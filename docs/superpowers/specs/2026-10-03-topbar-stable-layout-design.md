## 1. 背景与目标

### 1.1 用户诉求（原话）

> 「我发现一个简单的问题，就是在看月线、周线、日线这一块切换的时候，它这个UI总是会进行一个自适应变动。我感觉看起来很不舒服，意思就是能不能把它切改成那种固定格式的，然后只要不遮挡这个文字，看起来比较舒适就行。就是那一行，我不知道是那一行的问题，还是只是他们的这几个按钮的问题。」

拆成三条可验收的需求：

| # | 需求 | 验收方式 |
|---|---|---|
| R1 | 切 日线 / 周线 / 月线 时，顶栏那一行**不再自适应变动** | 真实浏览器实测各周期下的盒模型尺寸 |
| R2 | **不遮挡文字**（不许截断、裁切、省略） | 检查 `scrollWidth == clientWidth`，且文案可读 |
| R3 | 切 严格 / 非严格 口径时同样稳定 | 同上，两种模式都测 |

### 1.2 用户自己的疑问

用户问「是那一行的问题，还是只是他们的这几个按钮的问题」。

**答案是两者都是，且以那一行为主。** 见 §2。

## 2. 诊断（实测，非推测）

工具：headless Chrome 154 + CDP（`Emulation.setDeviceMetricsOverride`），真实服务端数据
（`sh.000001`，`limit` 默认），窗口高度固定 1000。

### 2.1 现状：按钮折行的临界宽度是 1440px，不是 1600px

严格口径下，只改视口宽（周期固定 `day`）：

| 视口宽 | `.period` 按钮 | `.periods` 宽 | `.query` 宽 | `.stamp` 宽 | `.topbar` 高 |
|---|---|---|---|---|---|
| 1600 | **59.8 × 36** | 298.6 | 648.5 | 696.6 | 93 |
| **1440** | **44.4 × 56** | 209.4 | 537.5 | 656.7 | 110 |
| 1366 | 44.4 × 56 | 209.4 | 537.5 | 596.5 | 110 |
| 1280 | 44.4 × 56 | 209.4 | 537.5 | 526.4 | 110 |
| 1200 | 44.4 × 56 | 209.4 | 537.5 | 461.3 | 110 |
| 1024 | 44.4 × 56 | 209.4 | 537.5 | 318.0 | 144 |
| 900 | 44.4 × 56 | 209.4 | 537.5 | 217.0 | 192 |
| 800 | 44.4 × 56 | 209.4 | 537.5 | 117.8 | 311 |

**只要窗口不超过 1440px，按钮就一直折成两行**（高 36 → 56px）。

### 2.2 非严格口径把临界宽度推到 1600px 以上

`app.js:123` 把口径存进 `localStorage`（`readChoice(LS_MODE, MODE_ORDER, "strict")`），
所以口径是**粘性**的。非严格模式下那段 102 字的口径说明（`app.js:257`）把 `.stamp`
撑到 **850px**，实测在 **1600px 就已经折行**：

| 视口 1600 | 按钮 | `.topbar` 高 |
|---|---|---|
| 严格 | 59.8 × 36 | 93 |
| 非严格 | 44.4 × 56 | 110 |

⇒ 抖动的严重程度取决于用户上次选的口径。

### 2.3 三个独立的变动源

1. **`.stamp` 宽度**：696.6 → 850px。周期加「由日线聚合」、口径换文案都会改它。
2. **`.stamp` 行数**：3 → 4 行。「全史」那行（`app.js:234-236`）只在窗口数 ≠ 全史数时出现。
3. **后果**：`.query` 被挤压 → `.period` 折行（36 → 56px）→ `.topbar` 高 83 → 110px。

### 2.4 根因

`styles.css:103` `.periods` 自身没有 flex 规则，子元素 `.period` 是 `flex: 0 1 auto`
（计算值），而 `.stamp` 的宽度**完全由文字内容决定、没有任何约束**。
`flex: 0 1 auto` 允许按钮缩到内容宽度以下，`overflow: hidden` 再把多出来的部分裁掉。

**按钮是无辜的**：它是被 `.stamp` 抢走空间后的受害者。
`.brand`（158.9px）与 `.query` 左边缘（206.9px）在所有状态下都是固定的。

## 3. 被否决的方案

### 3.1 方案乙：原地预留固定尺寸

内容位置不变，给 `.stamp` 固定宽度 + 固定高度（按最坏 110px 预留），按钮 `flex: none`。

**否决理由**：顶栏常年按最坏情况偏高，严格口径下右侧长期空一块；且 102 字文案塞进
固定宽度后会折成 2–3 行，可读性反而变差。

### 3.2 方案丙：只冻结按钮 + 单行截断

每行 `white-space: nowrap` + `text-overflow: ellipsis`。

**否决理由**：绝对恒定，但窄窗口会截断文字 —— 直接违反 R2。

### 3.3 朴素修法：只加 `.stamp { flex: none }`

**这是实测否决的**，不是推测。注入 `.period{flex:none;white-space:nowrap}` +
`.stamp{flex:none}` 后：

| 视口宽 | 按钮 | `.periods` 宽 | `.stamp` 宽 | 文档需 | 溢出 |
|---|---|---|---|---|---|
| 1600 | 59.8 × 36 | 298.6 | 696.6 | 1600 | 否 |
| 1440 | 59.8 × 36 | **270.7** | 696.6 | 1440 | 否 |
| 1366 | 59.8 × 36 | 270.7 | 696.6 | **1430** | **是** |
| 1280 | 59.8 × 36 | 270.7 | 696.6 | **1430** | **是** |
| ≤1366 | 59.8 × 36 | 270.7 | 696.6 | **1430** | **是** |

两个问题：① `.stamp` 不再收缩 ⇒ **≤1366px 出现横向滚动条**（治抖动换来横向滚动）；
② `.periods` 被压到 270.7 < 按钮总和 298.6 ⇒ `overflow: hidden` **裁掉约 26px**，
最后一个「5分」按钮被切边 —— 违反 R2。

## 4. 设计

### 4.1 内容拆分：顶栏只留恒定 2 行

`app.js:237-241` 现在一次性写 4 行。拆成两处写入，**文案一字不改、一字不丢**。

**顶栏 `.stamp`（恒定 2 行，就是现在的第 1、2 行）**

```
sh.000001 上证指数 · 日线 · 截至 2026-09-30
线段 10（确认 9 / 未确认 1） · 中枢 2 · 买卖点 0
```

**新增 `#stamp-detail`（顶栏正下方、`.disclaimer` 上方，全宽）—— 恒定 2 行**

```
全史 80 段 / 13 中枢 / 6 买卖点（这里只画与窗口相交的部分） · 周线由日线聚合
第一类买卖点取自趋势背驰；趋势按 [DD,GG] 波动区间判（第20课中心定理二；GG/DD 不含离开段，不是中枢区间 [ZD,ZG]）
```

- **第一行** = 全史计数 + 周期来源。窗口 = 全史时（月线）全史计数是空串，
  但**空串也要占一个行盒**，否则月线比日/周线少一行。
- **第二行** = 口径，且**只有口径**。

> **实现中修正的一处设计缺陷**：§4.1 初稿把「周期来源」留在**第二行**
> （`周线由日线聚合 · <口径>`）。实测 800px 严格模式下日线 2 行、周/月 3 行 ——
> 前缀让口径多折一行，详情行差 17px，图表照跳。
> 把周期来源挪进第一行后，第二行在任何周期下**逐字相同** ⇒ 折行数相同 ⇒ 高度相同。

严格口径那一句就是 `app.js:54` 的 `TREND_BASIS` 逐字全文（68 字）；
非严格那一句是 `app.js:261` 的 102 字长文案。两句都**原样搬移，不改一字**：
全文的字符与顺序都没变，只有换行位置移动（「周线由日线聚合」与 `\n` 交换了位置，
` · ` 从第二行挪到第一行）。

之所以搬走口径而不是别的：口径说明**严格 68 字 / 非严格 102 字**，
是宽度与行数的最大变量；周期来源也是周期性变量。两者都必须在顶栏之外。

### 4.2 CSS（下面是**实现后**的真实内容）

> **★ 2026-10-03 第二次订正**：本节初稿（`flex: 1 1 auto; min-width: 0` +
> `@media (max-width: 860px)` 补丁）**实现后仍很难看**，用户当场否掉。
> 下面是订正后的真实内容；根因与教训见 §6.2。

```css
body {
  grid-template-rows: auto auto auto minmax(360px, 1fr);  /* ★ 弹性行必须最后一轨 */
}
.brand { flex: none; white-space: nowrap; }   /* 中文被压窄 = 逐字竖排，不是缩排 */
.field { flex: none; }
.period  { flex: none; white-space: nowrap; padding: 8px 14px; }  /* 按钮永不被压缩折行 */
.periods { flex: none; overflow: hidden; }                        /* 按钮条永不被裁切 */
.go      { flex: none; white-space: nowrap; } /* 缺它「看结构」会竖排成 58.3×78 */
.stamp   { flex: 1 1 380px; min-width: 380px; }  /* 只有它允许被挤，且挤到 380px 就整条掉行 */
.topbar  { flex-wrap: wrap; row-gap: 10px; }  /* 全局，不再用手算断点 */
.stamp-detail {                              /* 顶栏之外，全宽独立一行 */
  padding: 0 20px 8px; font-family: var(--mono); font-size: 12px;
  white-space: pre-line;                     /* 保留 \n，其余空白折叠 */
  line-height: 17px;   /* ★ 必须写死，理由见 §4.4 */
  min-height: 42px;    /* = 17×2 + 8 padding（`* { box-sizing: border-box }`） */
}

/* ★ 761–980px：把 `.stage` 从 46px 的书脊列里捞出来（既有 bug，见 §6.3） */
@media (max-width: 980px) and (min-width: 761px) {
  .stage { order: 1; } .watch-rail { order: 2; } .ledger { order: 3; }
}
```

**关键不是「冻结图注」，而是「冻结除图注外的每一格」。** 初稿让 `.query` 承担全部
收缩（`flex: 1`，且没有 `min-width: 0`），结果收缩压力顺着 flex 链传给了
`.brand` 和 `.stamp`：`.go` 被挤成 `58.3 × 78px`（「看结构」竖着排）、
`.brand` 被压到 65.8px（「缠论」上下叠）。中文没有「缩排」，只有**逐字竖排** ——
所以对中文 UI 来说，「允许被压缩」等于「允许变成竖排」。
现在挤压力只落在 `.stamp`（纯文本，自己折行是自然的），
`.stamp` 到 380px 就整条掉到第二行（`.topbar` 全局 `flex-wrap`）。

### 4.3 窄屏断点 860px 的由来 —— **已删除，此节保留为历史**

> **★ 已作废（2026-10-03 第二次订正）。** 那个 `@media (max-width: 860px)` 补丁
> **已从 `styles.css` 删除**。下面的算术没错，但它是在**错误的前提下**做的：
> 它假定顶栏必须挤在一行里，于是去手算「什么时候挤不下」。
> 真正的问题是**顶栏本来就不该挤在一行** —— 让 `.topbar` 全局 `flex-wrap`，
> 由 `.stamp` 的 380px `flex-basis` 自己决定何时掉行，比任何手算魔数都准，
> 也不会在窗口宽度落在魔数附近时出错。

顶栏最小需求 = 40（padding）+ 56（gap）+ 158.9（brand）+ 555（`.query` 的 min-content）
≈ **810px**。既有断点在 760px（`styles.css:611-613`），中间 760–810px 会溢出。
860px 留出余量。该断点只作用于 `.topbar` / `.stamp`，**不触碰 `.work` / `.rail` 的既有 760px 断点**。

### 4.4 两处「必须写死」的东西，都是实测逼出来的

**其一：`line-height: 17px`。** 初稿只写 `min-height: 36px`，留给 `normal`。
实测月线详情行比日/周线矮 3px（`42/42/39`）：月线第一行是**空**的，
而空行的行盒只按字体 strut 算，比含中文的行矮。写死 `line-height` 后每个行盒一样高，
`min-height` 也改成 2 行的真实盒高 42px。

**其二：`min-height` 而不是 `height`。** 窄屏下口径会折成 2 行，`height` 会把文字裁掉 ——
用户明确要求「只要不遮挡这个文字」。所以是**预留**：内容超过 2 行时盒子跟着长，
下方图表会下移一点（实测 1024px 及以下非严格口径 59px，严格 42px），
但**同一宽度下三个周期完全一致**，周期切换不再引起跳动。

> 备选：把「全史」行改成始终显示即可消除第一行空串，但会在窗口=全史时印出一句
> 语义可疑的话（「这里只画与窗口相交的部分」此时是废话）。**选了留空行，不发明文案。**

### 6.1 测试

原有两条约束**保留、未改**：`tests/web/test_frontend_watchlist.py:254`（`body.code` /
`body.name` /「截至」必须在**同一源码行**）、`:231-236`（`TREND_BASIS` 或 `basisLine`

**新增**回归护栏 `tests/web/test_frontend_watchlist.py:260`
`test_topbar_stamp_is_pinned_to_two_short_lines`：断言顶栏 `setStamp` 的参数里
没有 `basisLine`、没有「全史」、**恰有 1 个 `\n`**，且 `index.html` 里
`id="stamp-detail"` 出现在 `</header>` **之后**。

> 写这条护栏时**先让它红**：第一版取错了调用点（取到 `:196` 的 `setStamp("加载中…")`），
> 红是红了，但红在错误的理由上（`assert 0 == 1`）。加了 `must_contain` 选中主调用点后

**第二次订正又补两条**（见 §6.2）：

| 护栏 | 拦什么 |
|---|---|
| `test_topbar_controls_cannot_be_squeezed_into_vertical_text` | `.brand` / `.field` / `.go` 缺 `flex: none` + `nowrap`；`.stamp` 缺 380px 下限；`.topbar` 缺 `flex-wrap` |
| `test_body_grid_rows_cover_every_body_child` | `body` 行数 ≠ 会产生盒子的子元素数，**或**弹性行不在最后一轨 |

> 它一开始只数轨道数（`4 == 4`）。用 HEAD 的旧 CSS 做反向验证时才发现：

#### 6.2.1 第二次订正：**「不跳」不等于「好看」，而我只测了前者**

> 用户看完第一版后当场否掉：
> 「不是吧？这改成什么什么样子了？你自己截图看一下好吧？那已经丑的不能再丑了，
> 这大部分的这个留白，还有上方这个看结构，这三个字竖着放那，你觉得合适吗？」

**这是本次任务最重要的一条教训。** 第一版的验收判据是
「顶栏高在每个宽度下三个周期完全相同」+「无裁切」+「无横向溢出」——
三条**全部通过**，54 行取样全绿。但页面**很难看**，而且难看的成因**没有一条**
被那三个指标覆盖：

| 缺陷 | 为什么原判据看不见 |
|---|---|
| 免责声明下 245px 空白 | 不是横向溢出，是**纵向**多出来的行高；顶栏高度也完全没变 |
| 「看结构」竖排成 58.3×78 | `.period` 的尺寸被断言了，`.go` 的**没被断言** |
| 「缠论」竖排 | 同上，`.brand` 也没被断言 |
| `.stamp` 被压成 129.3px 细缝 | 它**确实**在折行（原判据要的就是它折行），只是折得太窄 |

⇒ **两条纪律**：

1. **布局改动不许只用「高度 / 裁切 / 溢出」验收 —— 必须看一张真人视角的截图。**
   这三个指标是**必要**条件，不是**充分**条件。第一版正是「所有测试都绿、页面是坏的」。
   本次补拍 1280px 截图后才看见那四个缺陷。
2. **中文 UI 里「允许被压缩」= 「允许变成竖排」。** 英文单词被压窄只是缩排或换行；
   中文没有词内空白，盒子一窄于一个字宽就**逐字竖排**。所以对中文顶栏，
   除唯一那个「本来就要折行的纯文本格」之外，**每一格都必须 `flex: none`**。

**根因一：`body` 的行模板把弹性行给错了人。** `body` 是 grid，行模板
`auto auto minmax(360px, 1fr) auto` 是 4 轨，`body` 也正好有 4 个会产生盒子的子元素
（顶栏 / 详情行 / 免责声明 / 工作区）—— **数目完全对得上**，所以「数轨道数」的护栏
也拦不住。错的是**顺序**：插 `#stamp-detail` 时只想着「加一格」，
把新的 `auto` 追加到了末尾，于是 `1fr` 从工作区那一格**前移**到了免责声明那一格。
免责声明吃掉整屏剩余高度，工作区掉进隐式行。
⇒ 修法：`auto auto auto minmax(360px, 1fr)`，**弹性行永远在最后一轨**。

**根因二：`.query { flex: 1 }` 的 min-content 地板。** 它让收缩压力全部传给
`.brand` 和 `.stamp`，而这两个都没有 `flex: none`。
⇒ 修法：顶栏里除 `.stamp` 外全部 `flex: none` + `nowrap`，挤压力只落在 `.stamp`；
`.stamp` 给 `flex-basis: 380px`（实测阈值：低于它，图注会折成 3 行把顶栏撑高），
`.topbar` 全局 `flex-wrap` —— **手算断点（§4.3 的 860px）就此删除**。

**复测结果**（同一探针、同一 54 行）：仍**全部恒定**；顶栏高 **103 → 77px**（≥1280px），
「看结构」`58.3×78 → 90.7×38`，「缠论」恒 `158.9×28`。
即：**修好看的过程没有牺牲任何原有不变量**。

### 6.3 顺带查出的既有 bug：≤980px 时 K 线图只有 46px 宽

**与顶栏改动无关**（用运行时注入 HEAD 版 CSS 的 A/B 复现过：900px 下新旧
`grid-template-columns` 都是 `46px 854px`，`.stage` 都是 46px 宽，只有 y 坐标不同）。
但它是同一类「页面看起来是坏的」，且是**截图才看见的**，所以一并记下并修掉。

`.work` 在 ≤980px 变成 `46px minmax(0, 1fr)`，`.watch-rail` 抢了
`grid-column: 1 / -1`（整行），auto-placement 的游标被推到下一行，
`.stage`（没有 `grid-column`）就落进没人要的 46px 书脊列。
实测 900px：`#chart` = `[0, 1274, 46, 420]`，书脊右边 854px 全空。

修法：在 `@media (max-width: 980px) and (min-width: 761px)` 里用 `order`
把 `.stage` 提到 `.watch-rail` 之前 —— auto-placement 走的是 **order-modified 文档序**，
所以顺序变成 书脊 r1c1 / 图 r1c2 / 自选股 r2 整行 / 结构清单 r3。
`.ledger` 也必须显式给 `order`，否则它（默认 0）会排到 `.stage` 前面。
**限定 761px 以上**：≤760px 只有一列、自带另一套排布，不去动它。

修后 `#chart` 在 980/900/800/761px = **934 / 854 / 754 / 715px**，全宽度无横向溢出。
