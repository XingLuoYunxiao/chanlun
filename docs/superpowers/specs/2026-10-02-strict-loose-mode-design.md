## 1. 背景与目标

### 1.1 用户诉求（原话）

> 「我发现现在的这个其实是非常严格的那一种然后我想就是能不能有一个按钮可以切换为不是很严格的那种算法。就现在的这个买卖点我感觉就很少很少。然后我希望能优化一下这一块，就切为那切换为那种非严格的算法，就是有一定程度上严谨，胜率有百分之七八十就可以。然后还有就是它能不能把那个背驰的那个那个点也标注一下，比如说是有一个趋势背驰或者是盘整背驰，然后如果发生了背驰，我希望也标注一下。」

拆成三条可验收的需求：

| # | 需求 | 验收方式 |
|---|---|---|
| R1 | 一个按钮切换「严格 / 非严格」算法 | 页面顶部工具栏可见、可切换、状态可分享（URL） |
| R2 | 非严格模式买卖点明显变多，且**胜率 70%~80%** | 用现有回测框架实测胜率 |
| R3 | 图上标注背驰点，区分**趋势背驰 / 盘整背驰** | 两种模式下都标注 |

### 1.2 用户诉求的量化根据

前序审计已测得（`random.seed(7)`，117 只 ≥250 根日线的标的）：

- 买卖点合计 **154** 个，平均 **1.32 个/只**
- **零信号标的 23/117 = 20%**
- 按类型：`b3` 74、`s3` 71、`b1` 5、`b2` 2、`s1` 1、`s2` 1
  ⇒ **第一、二类合计仅 9/154 = 5.8%**，第三类占 **94%**

即「买卖点很少」的观感是准确的，而且结构上偏科：**几乎只有第三类**。

## 2. 前置修复：回测触发判据（P0，必须先做）

### 2.1 症状

```
python -m chanlun backtest --codes sh.600000,sh.601088,... --start 2018-01-01 --period day
→ 回测完成：0 笔成交 / 0 个回合 / 0 笔拒单
```

报告里胜率、盈亏比、期望全部显示 `—`。

### 2.2 度量证据（可复现）

**证据 A —— 旧判据从未成立。**

探针遍历 6 只票的每一根 bar，物理截断重算后统计 `sig.confirmed_at == bar.ts`：

| 票 | 信号数 | `confirmed_at` 曾等于当日 |
|---|---|---|
| sh.600000 / sh.601088 / sz.300750 / sz.000001 / sz.002415 / sz.300059 | 129 | **0 / 129 = 0%** |

⇒ `ChanSignalStrategy.on_bar`（`src/chanlun/backtest/strategy.py:113-134`）要求
`sig.confirmed_at == bar.ts`，该条件**在结构上不可能成立**，所以 0 笔成交是
**通用缺陷，不是某只票的问题**。

**证据 B —— `confirmed_at` 系统性早于「首次可见」。**

逐 bar 走 `step()`，对每个结构记录「首次以 CONFIRMED 状态出现的那根 bar」
（= 真正可知的时刻）与它自带的 `confirmed_at`：

| 票 | 观测到首次确认的结构 | 其中 `confirmed_at` **早于**首次出现 |
|---|---|---|
| sh.600000 | 121 | **121 / 121 = 100%** |
| sh.601088 | 158 | **158 / 158 = 100%** |
| sz.000001 | 146 | **146 / 146 = 100%** |

**证据 C —— 反方向 0 例。**

同一批走查中，`step.confirmed_at > full.confirmed_at` 出现 **0** 次。
（`tests/chan/test_engine.py:205-208` 断言的 `step <= full` 成立。）

### 2.3 根因

**回测把两个语义不同的时间混为一谈：**

| 概念 | 定义 | 归属 |
|---|---|---|
| `confirmed_at` | **结构自身的确认完成时刻** | 结构的属性 |
| 首次可见 | **引擎第一次产出它的那根 bar** | 观测过程的属性 |

两者系统性不等（证据 B：100%）。

落点链条：

1. `src/chanlun/chan/segment.py:363-396` `_make_segment`：
   `confirmed_at = strokes[ci].confirmed_at or strokes[ci].end.ts`
   —— 线段继承「确认它被破坏的那一笔」的确认时间，这是**结构内部**的时间，
   不是引擎产出它的时间。
2. `src/chanlun/chan/state.py::confirm_at`：**「写一次永不改」**——
   `_reconcile_field` 对新出现的 CONFIRMED 结构调用
   `confirm_at(new_item, as_of if ts is None else ts)`，由于 `ts` 非空，
   这个偏早的值被**原样保留**。
3. `src/chanlun/backtest/runner.py:186`：`_view(engines[code].full(frame), bar.ts)`
   —— 用的是 `full()`，不经过 `reconcile()`，连上面那点保护都没有。
4. `src/chanlun/backtest/strategy.py:113-134`：拿 `confirmed_at` 当「今日新可知」用。

**注意第 4 步才是 bug 本身。** 前三步产出的 `confirmed_at` 是**自洽的**，
它回答的是「这个结构的确认何时完成」，不是「我何时第一次看见它」。

### 2.4 被否决的替代方案

| 方案 | 否决理由 |
|---|---|
| 改 `_make_segment`，让 `confirmed_at` 等于首次可见 | **不可行**：`full()` 无法知道首次可见（它只看得到当前帧）。且会让 `step.confirmed_at > full.confirmed_at`，**打破 `tests/chan/test_engine.py:205-208`**（证据 C：该断言实测 0 例外）。 |
| 改 `_reconcile_field`，新出现的 CONFIRMED 结构一律记 `as_of` | 同上，会让 `step > full`，破坏不变量；且只修了 `step()` 路径，回测走的是 `full()`。 |
| 回测改用 `step()` 增量推进 | 不解决根因（`confirmed_at` 仍是结构时间），且 `step()` 内部同样跑完整 `_compute`，无性能收益。 |
| 保留 `confirmed_at`，另加 `first_seen` 字段 | 需要一份「从第一根 bar 起完整重放」的持久化状态，回测每只票本来就在重放，多存一份是冗余。 |

### 2.5 采纳的修法

**在回测的读取路径上显式区分「可见」与「新可知」。**

`runner.py` 本来就在**逐 bar 物理截断重算**，所以「首次可见」是**免费**的：

```python
visible = backtestable(snap.signals, as_of)   # 快照里此刻已确认的信号
fresh   = [s for s in visible if key(s) not in seen]   # 本 bar 才第一次可知的
seen   |= {key(s) for s in visible}
```

`key(s)` 用信号身份（`kind + ts + price`），不用列表下标。

- `strategy.py::ChanSignalStrategy.on_bar` 去掉 `confirmed_at != bar.ts` 闸门，
  契约改为：**「传进来的信号就是本 bar 新可知的信号」**。
- `runner.py::_view` 增加显式的信号入参，不再隐式依赖 `backtestable` 的全量结果。

**已验证有效**（8 只票，全历史）：

| 判据 | 触发次数 | 回合 | 胜率 |
|---|---|---|---|
| 旧（`confirmed_at == bar.ts`） | **0** | 0 | — |
| 新（首次可见） | **22** | 9 | 4/9 = **44.4%** |

### 2.6 顺带更正的文档不实陈述

`src/chanlun/chan/engine.py` §3/§4 与 `src/chanlun/chan/state.py::backtestable`
的 docstring 声称 `confirmed_at` 已记下「什么时候才知道它成立」。
证据 B 以 **100%** 的反例否证了这句话。改为如实描述：
`confirmed_at` 是**结构自身的确认完成时刻**；点时可交易时刻必须由
「首次可见」给出（回测路径见 §2.5）。

## 3. 原文依据

判据变更必须先有原文（AGENTS.md §5）。以下摘录**逐字**取自
`chanlun108/原文/`，未改写。

### 3.1 盘整背驰 —— 一手原文

**第 039 课《同级别分解再研究》L31：**

> 把a定义为A0，则Ai与Ai+2之间就可以不断地比较力度，用盘整背驰的方法决定买卖点。
> ……只理会一点，就是Ai与Ai+2之间是否盘整背驰，只要盘整背驰，就在i+2为偶数时卖出，
> 为奇数时买入。

**第 039 课 L35：**

> 以上的方法，最大的特点是，就是在同级别分解的基础上将图形基本分为两类，
> 一类是"当i为偶Ai+3不跌破Ai高点"或"i为奇数Ai+3不升破Ai低点"；
> 一类是"Ai与Ai+2之间盘整背驰"。

⇒ **可机械化的判据**：同向的 `Ai` 与 `Ai+2` 比较 MACD 面积，收缩即盘整背驰。

**第 060 课《图解分析示范五》L41：**

> 站在最严格意义上，45-46线段构成43-44线段的盘整背驰（注意，力度比较的是下面所有红柱子的面积之和。）

⇒ 线段级盘整背驰**存在「线 vs 线」的比较形态**，且力度比较要用**同色柱面积之和**
（与现行 `macd.py::hist_area` 的分色口径一致）。

**第 037 课《背驰的再分辨》L21：**

> 没有趋势，没有背驰……这样，是不存在背驰的，最多就是盘整背驰。

⇒ 盘整背驰是**与趋势背驰并列**的独立类别，不是趋势背驰的弱化版。

### 3.2 盘整背驰**不能**叫第一类买点 —— 一手原文

**第 060 课 L45：**

> 显然，46-55是一个5分钟的中枢，55跌破53后明显盘整背驰，各位也不难发现，
> 如果把55当成第一类买点（严格来说，盘整背驰无所谓第一类买点，只是这样来类比），
> 57就是一个第二类买点。

⇒ **硬约束**：盘整背驰产生的买点只能**类比**为第二类，**不得**并入第一类。

### 3.3 第二类买点**定义上依赖**第一类 —— 一手原文

**第 101 课《答疑1》L31：**

> 其实，所谓第二类买点，就是第一类买点的次级别回抽结束后再次探底或回试的那个
> 次级别走势的结束点。

**第 021 课《缠中说禅买卖点分析的完备性》L35：**

> 第二类买点是和第一类买点紧密相连的，因为出现第一类买点后，必然只会出现盘整与
> 上涨的走势类型，而第一买点出现后的第二段次级别走势低点就构成第二类买点。

⇒ 现行「第二类需前置第一类」是**原文正确**的，不得直接删除。

### 3.4 第二类的独立路径 —— 一手原文（这是放宽 #2 的真正依据）

**第 027 课《盘整背驰与历史性底部》L49：**

> 类似的，在大级别里，如果不出现新低，但可以构成类似第二类买点的买点，
> 在MACD上，显示出类似背驰时的表现，黄白线回拉0轴上下，而后一柱子面积小于前一柱子的。

⇒ **原文自己给出了「盘整背驰 → 类第二类买点」这条独立路径**，且明确用「类似」措辞。

**第 101 课 L51：**

> 第二类买点跌破第一类买点，也就是第二类买点比第一类买点低，这是完全可以的，
> 这里一般都构成盘整背驰

⇒ 第二类与盘整背驰在原文里本就经常同现。

### 3.5 第三类买点「必须是第一次」 —— 核实结论：**现行代码已满足，不需要改**

**第 020 课《缠中说禅走势中枢级别扩张及第三类买卖点》L59：**

> 由定理一，可以得到第三类买卖点定理：一个次级别走势类型向上离开缠中说禅走势中枢，
> 然后以一个次级别走势类型回试，其低点不跌破ZG，则构成第三类买点；
> 一个次级别走势类型向下离开缠中说禅走势中枢，然后以一个次级别走势类型回抽，
> 其高点不升破ZD，则构成第三类卖点。

**第 020 课 L69：**

> 但一定要注意，并不是任何回调回抽都是第三类买卖点，必须是第一次。

**核实过程**（我最初判断「代码漏了这条过滤」，**该判断是错的**，记录在此以免重犯）：

1. `src/chanlun/chan/pivot.py:168-173` 的中枢延伸循环
   `while j < n and j - i < MAX_SEGMENTS and _overlaps(confirmed[j], zd, zg)`
   —— 中枢在**第一个完全不碰 `[zd, zg]` 的段**处封闭，`end_idx = positions[j-1]`。
2. `src/chanlun/chan/signal.py:167` 唯一取用的回试段就是 `segs[p.end_idx + 1]`
   —— 它**就是**「离开中枢后的第一次回抽」，结构上不可能取到第二次。
3. `src/chanlun/chan/pivot.py:221` 的 `i = j` 保证相邻中枢的 `end_idx` 严格递增，
   同一次离开不会重复产出信号。

**一度误判为偏离的度量（已作废）**：探针统计「中枢组内部在最后一段之前是否已有段
越过 ZG」——40 只票 / 64 个第三类信号中命中 **50 个（78%）**。
但这是**中枢延伸的正常形态**。第 020 课中心定理一原文：

> 走势中枢的延伸等价于任意区间[dn，gn]与[ZD，ZG]有重叠。

组内同向段只要 `dn <= ZG` 就仍在延伸，`gn` 完全可以远高于 ZG
（实测例：`600537` 的 ZG=5.4，组内某段最高 8.79）。
⇒ **该度量测量不到「第一次」这件事**，不能作为偏离证据。

**结论**：严格模式的第三类**保持现状，不加过滤**。
非严格模式若要「允许非第一次回抽」，那是**放宽**、且**违反**第 20 课 L69，
属于工程口径（见 §4.2）。

### 3.6 第三类「容忍度」= 原文空白项

原文在这一点上是**一致且严格**的，没有任何「允许小幅回到中枢」的措辞：

- 第 020 课 L59：「其低点**不跌破**ZG」
- 第 024 课 L89：「其后的次级别回跌并**不重新回到**前面的中枢里」
- 第 032 课 L39：「如果一个5分钟级别的回拉**不回到**中枢里，就意味着有第三类买点」
- 第 033 课 L51：「次级别回抽一旦**不重新回到**中枢里，就意味着第三类买点出现了」

⇒ **结论：第三类容忍度没有任何原文依据。**
它必须被标注为**工程口径**（可调参数、默认只在非严格模式生效），
**不得**在文档或 UI 中表述为缠论判据。

## 4. 设计

### 4.1 口径模型

新增一个正交维度 `SignalMode`，取值 `STRICT` / `LOOSE`。

**作用域边界（硬约束）**：

> 严格 / 非严格**只影响「买卖点」与「背驰标注」**。
> **笔、线段、中枢的划分口径完全不动** —— 即不触碰 round-018~020
> 刚改严的 `segment.py`（标准特征序列、`_ordinal_ok`、左边 argmax）。

理由：划分是**结构**，买卖点是**结构上的判读**。禅师对划分的要求
（第 67/71/78/79 课）没有「宽松版」；对买卖点的判读则明确存在
「最严格意义」与「实际操作」的分层（第 060 课 L41 原话：
「站在最严格意义上……当然，这是按最严格的，并没有太大操作意义的分析」）。

**推论（可作回归断言）**：严格模式的买卖点结果应与改动前**逐项相同**。

### 4.2 严格 / 非严格判据对照表

| 买卖点 | 严格模式（= 现行，**全部不动**） | 非严格模式 |
|---|---|---|
| 第一类 | 趋势背驰：两个同向中枢 + 新极值 + 面积收缩 | **同严格**（第37课「没有趋势，没有背驰」，不放宽） |
| 第二类 | 需前置第一类 | 需前置第一类 **或** 盘整背驰「类第二类买点」（第27课 L49） |
| 第三类 | 位置判据（第20课 L59/L69 已由中枢构造天然满足，见 §3.5） | 位置判据 **+ 容忍度 `tol`**（工程口径）+ 放宽「必须是第一次」（工程口径，**违反**第20课 L69） |
| 盘整背驰买卖点 | **不产生买卖点**，只标注 | 产生独立类型 `pb` / `ps` |

**关于第一类为什么不放宽**：曾考虑「趋势从两个同向中枢降到『一个中枢+创新极值』」，
已否决 —— 第 037 课 L21 明确「没有趋势，没有背驰」，一个中枢不构成趋势。

### 4.3 背驰标注

两种模式**都标注**，区分两类：

| 类型 | 判据 | 原文 |
|---|---|---|
| **趋势背驰** | 两个同向中枢 + 新极值 + 同色面积收缩 | 第 037 课 L21、第 020 课中心定理二 |
| **盘整背驰** | 同向 `Ai` 与 `Ai+2` 同色面积收缩（中枢内或全局） | 第 039 课 L31、第 060 课 L41 |

**只有非严格模式**把盘整背驰转成买卖点（`pb`/`ps`）—— 符合第 060 课 L45
「盘整背驰无所谓第一类买点」。

第 049 课 L71 的区分必须保留为**标注属性**：

> 中枢震荡中出现的类似盘整背驰的走势段，与中枢完成的向上移动出现的背驰段是不同的，
> 两者分别在第三类买点的前后……这是有严格区分的。

⇒ `Divergence` 记录 `in_pivot: bool`，UI 上可区分「中枢内震荡盘整背驰」与
「离开中枢后的盘整背驰」。

### 4.4 数据模型

**新增 `src/chanlun/chan/divergence.py`：**

```python
class DivergenceKind(str, Enum):
    TREND = "trend"                  # 趋势背驰（第37课）
    CONSOLIDATION = "consolidation"  # 盘整背驰（第39/60课）

@dataclass(frozen=True)
class Divergence:
    idx: int
    kind: DivergenceKind
    direction: int          # 1 = 顶背驰（看跌）, -1 = 底背驰（看涨）
    ts: str
    price: float
    level: str
    seg_idx: int            # 当前段在 segments 里的下标
    ref_seg_idx: int        # 被比较的参照段
    area_now: float
    area_prev: float
    ratio: float            # area_now / area_prev
    new_extreme: bool       # 是否创了新极值（第27课 L49 的「不出现新低」分支）
    in_pivot: bool          # 是否在中枢内（第49课 L71 的区分）
    pivot_idx: int | None
    reason: str             # 原文引句
    status: Status = Status.CONFIRMED
    confirmed_at: str | None = None
    src_start: int = 0
    src_end: int = 0

def find_divergences(bars, segments, pivots, level="day", macd_df=None) -> tuple[Divergence, ...]: ...
```

**`Snapshot` 新增字段 `divergences: tuple[Divergence, ...] = ()`。**

- 在 `engine.py::_compute` 里计算（`find_divergences` 与 `signal_fn` 并列调用）。
- **不进 `state.py::_FIELDS`** —— 它是**派生数据**：完全由 `segments` + `macd`
  决定，而这两者的 point-in-time 语义已由各自字段的调和保证。
  进 `_FIELDS` 会引入一份无独立身份、却要参与调和的冗余状态。

### 4.5 买卖点判据

### 5.2 R2 —— 胜率（核心验收）

**协议**（用户已批准）：现有回测框架 · 信号确认日**次日开盘**买入 ·
出现卖点卖出 · 日线 · 全市场抽样。

| 指标 | 严格模式 | 非严格模式 | 目标 |
|---|---|---|---|
| 买卖点总数 | 基线 | **显著增加** | 零信号标的 23/117 → 明显下降 |
| 回合数 | 基线 | 增加 | — |
| **胜率** | 已测 **44.4%**（9 回合，样本过小） | **待测** | **70% ~ 80%** |

**样本量要求**：≥100 只标的（固定随机种子），保证回合数 ≥100，
否则胜率不可信（9 回合的 44.4% 只能当量级参考，不能当基线结论）。

**已知成本**：`runner.py` 每根 bar 调一次 `store.read(...)`，是 O(n²) I/O。
全历史 × 100 只预计数十分钟。缓解：验收跑用**内存切片**（`df.iloc[:k]`）替代重复
读盘，并**先验证内存切片与真实 runner 在同一子集上结果一致**，再放大样本。

**若胜率落在 70%~80% 之外**：只在**已批准的判据集内**调参
（`tol` 容忍度、盘整背驰的面积比阈值），**不得**新增无原文依据的规则。
