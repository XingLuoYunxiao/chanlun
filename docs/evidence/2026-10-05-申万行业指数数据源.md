## 2. 走通的入口：腾讯**板块**列表接口

```bash
curl -s "https://proxy.finance.qq.com/cgi/cgi-bin/rank/pt/getRank?board_type=hy&sort_type=price&direct=down&offset=0&count=200"
```

回 `{"code":0,"msg":"ok","data":{"rank_list":[{"code":"pt01801120","name":"食品饮料","stock_type":"BK-HY-1",…}]}}`。

`board_type` 决定级别，**实测计数正好等于申万官方口径**：

| `board_type` | 条数 | `stock_type` | 含义 |
|---|---|---|---|
| `hy` | **31** | `BK-HY-1` | 申万**一级**行业 |
| `hy2` | **124** | `BK-HY-2` | 申万**二级**行业 |
| `hy3` | 0 | — | 不存在 |
| `gn` | 200 | `BK-GN` 185 / `BK-GN-FG` 15 | 概念板块（本期不做） |

- **`count` 必须 ≤ 200**：`count=500` ⇒ `{"code":1619377101,"msg":"error_type=2 suggest=2 msg=参数错误:count too large"}`。
  翻页用 `offset`：`hy2` `offset=0` ⇒ 124 条，`offset=100` ⇒ 24 条。
- **板块代码 = `pt01` + 申万 6 位码**：`pt01801120` → `801120` 食品饮料；
  `pt01801125` → `801125` 白酒Ⅱ；`pt01801054` → `801054` 小金属。
- **一级码尾数恒为 `0`（`801x x0`），二级码尾数为 `1–9`。**
  实测两个集合**交集为空**（`sorted(l1 & l2) == []`，并集 155），
  所以 `801xxx` 这个码段虽然共用，**不存在一级/二级撞码**。
  这是**实测结论，不是接口承诺** —— `industry.py` 的 `test_the_two_levels_do_not_share_a_code`
  每次都重算一遍，不靠假设。
- 一级 31 个名称（逐字）：食品饮料, 家用电器, 电力设备, 电子, 医药生物,
  有色金属, 社会服务, 通信, 汽车, 建筑材料, 银行, 计算机, 基础化工, 综合,
  美容护理, 煤炭, 石油石化, 农林牧渔, 公用事业, 钢铁, 机械设备, 轻工制造,

## 3. 板块日线只能走 `newfqkline`，而且 `param` 有个尾巴逗号

```bash
curl -s "https://proxy.finance.qq.com/ifzqgtimg/appstock/app/newfqkline/get?param=pt01801120,day,,,640,qfq"
```

`data.pt01801120` 的键是 `['day','prec','introduce','version']`，
`day` 是**11 字段**的行：

```
["2024-02-07","18234.74","18526.96","18526.96","18191.70","15615500.00",{},"1.80","3884437.00","0.00","0.00"]
  日期        开         收        高         低         量(手)       {}  涨跌幅   成交额(万元)
```

**★ 第 3 个字段是「收」，第 4 个才是「高」** —— 不是 OHLC 顺序。
`_rows_to_frame` 就按这个位置读，`test_the_row_fields_are_read_in_the_vendors_order_not_ohlc`
钉住它（把 `close`/`high` 对调，这条测试**会红**）。

**成交额单位是万元**（同 `hkfqkline` 路径的 `_AMOUNT_IDX = 8` / `_AMOUNT_SCALE = 10_000.0`）。
对照 `sh000001`：第 8 字段 `49591987.81` 万元 ≈ 4959 亿元，正是上证 2024-02 的日成交额。
板块自洽：`pt01801120` 的 `2502343.00` 与 `getRank` 的 `turnover` 一致。

**★ `param` 是 7 段，末段（复权词）必须留空位：**

| `param` | 结果 |
|---|---|
| `pt01801120,day,,,5,` | 键 `day`，5 根 |
| `pt01801120,day,,,5` | `{"msg":"bad params"}`，0 根 |
| `pt01801120,day,,,5,qfq` | 键 `day`，5 根（板块无所谓复权） |

**★ `count` 上限 2000**：`640` ⇒ 640；`1000` ⇒ 1000；`2000` ⇒ 2000；
`2500`/`3000`/`3200`/`4000` ⇒ `{"msg":"param error"}`，且此时 **`data` 是一个 `list`**
（不是 dict —— 直接 `.get` 会 `AttributeError`，`_node` 的 `isinstance` 判断就是拦它）。

**★ `start` 被完全忽略，`end` 被采纳且含当天**（实测 n=5）：

| `end` | 该页最后一根 |
|---|---|
| `2018-07-05` | `2018-07-05` |
| `2018-07-06` | `2018-07-06` |
| `2018-07-09` | `2018-07-09` |

`param=…,day,2020-01-01,2020-12-31,2000,` 与 `param=…,day,,2020-12-31,2000,`
**逐字节相同** —— 显式 `start` 零作用。

**★ 行是升序（最老在前）**：`_page("pt01801120","2026-09-30")` ⇒
`rows[0][0] == "2018-07-06"`、`rows[-1][0] == "2026-09-30"`。

**★ 板块没有分钟线**（对照过）：`mkline?param=pt01801120,m30,,320` ⇒
`{"code":-1,"msg":"param error","data":[]}`；`m5` 同。对照 `sh600000,m30,,320` /
`m5` 都回 `{"code":0,…}` ⇒ **板块只有日线**，周/月由日线本地聚合。

**★ 普通 `fqkline` 对板块不可用**：`param=pt01801120,day,,,640,qfq` ⇒ 键
`['day','prec','version']`，**只有 1 根**（最新那根）；带区间 ⇒ 0 根。

## 4. 翻页：减一天 ⇒ **零重叠**（一次自我更正）

`_paged_day` 从 `end` 往回翻，下一页的 `end` 取「上一页**最老**那根 − 1 天」。

```bash
PYTHONPATH=src ../.venv-chanlun/bin/python -c "
from chanlun.data import sw_source
orig = sw_source._page
def spy(sym, end):
    r = orig(sym, end)
    if r: print('页 end=%s n=%d %s..%s' % (end, len(r), r[0][0], r[-1][0]))
    return r
sw_source._page = spy
df = sw_source._paged_day('pt01801120','1990-01-01','2026-09-30')
print('合计', len(df), '唯一', bool(df['ts'].is_unique))
"
```

实测输出：

```
页 end=2026-09-30 n=2000 2018-07-06..2026-09-30
页 end=2018-07-05 n=2000 2010-04-15..2018-07-05
页 end=2010-04-14 n=1492 2004-03-01..2010-04-14
合计 5492 唯一 True
```

**2000 + 2000 + 1492 = 5492，一根不重。**

> **⚠️ 后续更正（2026-10-05，`0.6.0`）**：本文件初稿（与 `sw_source.py` 的模块
> 注释）曾写「相邻两页重叠 1 根，`2000 + 2000 + 1494 = 5494 行`，去重后 5492 根」。
> 那是**探测脚本的产物**：那版探测把下一页的 `end` 传成 `上一页首行`（**没有减一天**），
> 于是边界那根被取了两遍，第三页因此多出 2 根。落库代码里 `nxt = first - 1 day`
> 一直是减了的 —— **代码没错，注释错了**，已按上表改写。
> `normalize` 的 `drop_duplicates(subset=["ts"], keep="last")`
> （`types.py:101`）仍然留着，但它是**兜底**，不是这一步的依靠。
>
> 另一处顺带更正：`end` 的语义早先记成「含当天」但没测边界，现已用 n=5 实测钉死（§3 表）。

**最早一根是 `2004-03-01`**，而申万基日是 1999-12-30 ——
腾讯的板块历史**只到 2004 年**，这是数据商的边界，照实记，不谎报。

## 5. 落库与口径

| 项 | 值 | 依据 |
|---|---|---|
| 落库键 | `sw.801120` / `sw.801125` | `markets.MARKETS` 加 `"sw"`；`SW_SYMBOL_RE = ^801\d{3}$` |
| 板块符号 | `pt01801120` | `industry.vendor_code()` = `VENDOR_PREFIX + 6 位码` |
| 落库路径 | `data/day/sw/801120.parquet` | `store.path_for` |
| 复权口径 | **不复权**（`adjust_for` ⇒ `"3"`） | 板块是指数，没有除权除息；`is_index` 显式认 `sw` |
| 周期 | 只有 `day`；`week`/`month` 由 `periods.aggregate` 本地聚合 | 板块无分钟线（§3） |

**★ 裸 `801120` 不接受，必须带 `sw.` 前缀。** `markets.HEAD2` 把首字符 `8` 映到 `bj`
（北交所），裸码会被解析成北交所股票 —— 和 `sh.000001` 一样，前缀是必需的。
`industry.vendor_code("801120")` 因此回 `""` 而不是「猜一个」，
`test_vendor_code_does_not_validate_against_the_bundle` 钉住这一点。

**★ 行数护栏判在裁剪之前**（`sw_source.py` 的 `MIN_ROWS` 那一段）：
腾讯只约束 `end`、不约束 `start`，一页通常回 2000 根，增量同步只要二十几个交易日
就会被本地裁成二十几根 —— **那是正确答案**。拿裁剪后的行数去比阈值，会把每一次
正常的增量同步都判成失败（同一个坑在 `tencent_source._paged_day` 已经踩过一次）。
护栏真正要拦的是「返回码正常但只回 1 根」的**静默假成功**。
红证明：把护栏挪到 `truncate` 之后量 `len(out)`，
`test_the_row_guard_runs_before_the_trim` 与 `test_start_and_end_are_trimmed_locally`
两条**同时变红**，报 `DataSourceError: pt01801120 的日线只回 10 行（少于 30）`。

**★ 键名漂移要拦死**：板块没有复权，键名应当是 `day`。哪天开始回 `qfqday`/`hfqday`，
说明数据商把板块也纳入了复权分派 —— 那种漂移**不报错**，只会让库里混进另一种口径的价格。
`_check_key` 直接 `raise`（红证明：关掉这个判断，
`test_the_expected_key_is_day_and_a_qfqday_is_refused` 变红）。

## 7. 静态清单 vs 联网取清单（D-44 的取舍）

31 + 124 条**写死在 `src/chanlun/data/industry.py`**，不建 sqlite 表、不在页面加载时联网。理由：

1. 搜索与 `meta.name_of` 都是**热路径**，一次网络往返会把「搜一下」变成「等一秒」。
2. 申万 2021 版分类几年才调一次；调的时候要**有人看见**，而不是悄悄变。
3. 先例：`meta.DEFAULT_WATCHLIST` 也是硬编码的 11 条。
4. 过期要**露出来**：`CHECKED_ON = "2026-10-05"` 随 `/api/industries` 的 `as_of`
   发到页面，下拉框下面显示「清单核对于 2026-10-05」——
   **悄悄过期比过期本身更坏**。
5. `python -m chanlun industry --check` 把「清单还是不是对的」变成一条**能失败**的命令：
   差异 ⇒ 退出码 1；**拉不到也算失败**（「核对失败」打到 stderr 并计入 `bad`），
   所以「拉不到」永远不会被读成「没问题」。`--check` **只报差异，不改清单**。
