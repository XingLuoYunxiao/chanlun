### A.1 缺陷 D1（数据层）：`normalize` 把非法价格变成 `0.0`

**位置**：`src/chanlun/data/types.py::normalize`

```python
for col in COLUMNS[1:]:
    out[col] = pd.to_numeric(out[col], errors="coerce")   # 解析不了 -> NaN
out = out.fillna(0.0)                                     # NaN -> 0.0  ← 病灶
```

**机理**：0 价不是行情，但代码把它当成了**真实的、史上最低的价格**。
`sz.399001` 日线那 5 根全 0 行让 `min(low) == 0.0` 成了全序列最低点，
分型把这个 0 当成一个真实的底，1995 年以来的整段走势被压到它身上 ——
这正是 §A.0 里那条 592 笔怪物段的来源。

**波及面**（全市场 5453 个 parquet 文件扫描，4.2 秒）：**4 个文件含非正价格**——
`sz.399001` 日线 5 根、`sh.600759` 30 分钟 22 根、`sh.600759` 5 分钟 **142 根**、`sz.300114` 日线 1 根。

**修复**：在 `normalize` 里剔除任一 OHLC ≤ 0 的行（含解析失败变成 NaN 的行），
并 `logger.warning` 报出条数。`volume` / `amount` 为 0 是正常的（停牌、无量），
**不在剔除范围**。补丁：`optimizer/patches/round-018-D1-nonpositive-price.patch`。

**为什么一处改动就够**：`normalize` 是**唯一收口**——`store.read` / `store.write` /
`store.upsert`、`engine.full` / `engine.step`、`data.tdx`、`data.periods`、
`data.baostock_source` 全部经过它。数据层修复天然覆盖所有入口。

### A.2 缺陷 D2（算法层）：`_structural_ok` 把「划分后标准化」提前成划分判据

**位置**：`src/chanlun/chan/segment.py`（原 `_structural_ok`，已删除）

第 78 课原文把「极值不在端点」明确放在**划分之后**：

> 就是，如果线段中，最高或最低点不是线段的端点，那么，在任何以线段为基础的分析中，
> 例如把线段为基础构成最小级别的中枢等，都可以把该线段标准化为最高低点都在端点。
> 因为，在以线段为基础的分析中，都把线段当成一个没有内部结构的基本部件，
> 所以，只需要关心这线段的实际区间就可以，这样就可以只看其高低点。

原文自己给了理由（「只需要关心这线段的实际区间就可以」），并紧接着说
「经过标准化处理后，所有向上线段都是以最低点开始最高点结束，向下线段都是以最高点开始最低点结束」。
而 `_make_segment` **已经在做**这个标准化（`high=max(...)`、`low=min(...)`）。
把同一件事**同时**当成划分的准入条件，是因果颠倒：等于要求线段在划出来之前就已经标准化。

**代价实测**（这是本轮最反直觉的一处）：

- 「极值不在端点」在真实数据上**很常见**：12 只标的的确认段里有 **40 余处**
  （`sh.600759` 5min 22 处、`sz.399001` 4 处、`sh.000905` 3 处……）。
  例：`sz.300059 segment 0` 向上线段 起点 7.33281563 / 低点 6.138223，
  终点 16.82038803 / 高点 16.82038803。
- 而「标准化本身失败」（`seg.high`/`low` 与笔区间真实极值不符）在 13 只标的、
  全部配置下都是 **0 处** —— `_make_segment` 的标准化是可靠的。
  **所以被 `_structural_ok` 否掉的，全是上面那批合法线段。**
- 否掉它们会在 `candidates(s)` 上凿出**可行性空洞**，使 `best(s)` 剧烈非单调。
  `sz.399006` 的实测：`candidates(22) = candidates(46) = candidates(80) = []`，
  而 `best(s)` 在 `s ∈ {0,20,40,60,80,100,120,140,160,180,200,220,240,260,280,300}`
  上取值 `{25,25,21,19,0,25,25,21,0,0,9,7,3,0,0,0}` —— 从 25 直接掉到 0。
  这就是 §A.0 那条 592 笔怪物段的直接机制。

**修复**（补丁 `optimizer/patches/round-018-D2-segment-standardization.patch`）：

1. **删掉 `_structural_ok`**；
2. 新增 `_ordinal_ok`，只否掉**序关系自相矛盾**的候选
   （向上线段先见最高点后见最低点），不再管极值在不在端点上；
3. 新增 `_extreme_problems`，把第 78 课的两条要求改成**事后校验**
   （`validate_segments(segs, strokes)` 会报「未按第 78 课标准化」与「先见最高后见最低」），
   校验失败**不推翻划分结果**；
4. 标准化**不移动** `start`/`end` —— 线段的端点是笔的端点，本来就该停在分型上，
   标准化只决定 `high`/`low` 两个区间端点字段。

**`_ordinal_ok` 对最终输出是无操作，保留它是加固而不是旋钮**：13 只标的
14727 个候选里它只否掉 **26 个（0.18%）**；把它强制成恒真后 13 只标的输出**逐位相同**。
处理方式与 `include.py` 的 `>` 改 `>=` 同类（可证无行为差异，见 §2.1）。
**谁把它当成段数旋钮，就会重犯下一段的错。**

**本轮曾走过一段弯路，必须记下来**：删除 `_structural_ok` 的过程中，
左端起点一度被改成「确认线段数最多的起点」（argmax），并用一条极值判据论证前导
TENTATIVE 段的合理性。实测该改动的代价是**把开头整片笔藏进不分类的前导段**：

| 左端选法 | `sz.399001` | `sz.399006` | 100 只样本 |
|---|---|---|---|
| **第一个可行起点（当轮主干）** | 55 段 / 最长 53 / 前导 0 笔 | 26 段 / 最长 87 / **前导 0 笔** | 1161 段 / 最长 93 / 前导 10 笔 |
| 段数最多的起点（当轮已否决） | 58 段 / 最长 53 / 前导 14 笔 | 31 段 / 最长 **102** / **前导 102 笔** | 1344 段 / 最长 76 / **前导 308 笔** |

argmax 只是为了绕开 `_structural_ok` 制造的可行性悬崖才加的**补偿**，
判据一删它的理由就没了；而它为了多算 183 段，把 308 笔藏进不分类的前导段 ——
**与用户抱怨的症状同类**。当轮**已回滚**，左端恢复「第一个可行起点」。

### A.3 为什么初版审计会漏掉（方法论失败）

漏掉的原因**不是**某一处代码没读，而是**取证样本与判据的结构性盲区**：

| 维度 | 初版审计的样本 | 缺陷显形所需的条件 |
|---|---|---|
| 时间跨度 | 2020-01-01 起（≤ 6.7 年，≤ 1635 根） | **长历史**：`sz.399001` 需 8648 根才走到 1995 年那 5 根 0 价 K 线 |
| 标的类型 | 24 只**个股** | **指数**：`sz.399001` 是唯一含 0 价的指数；指数还带超长单边段 |
| 数据质量 | 未注入过脏数据 | **停牌/缺值**：0 价行只出现在停市占位处 |

### A.6 缺陷 D3（算法层）：非包含处理没有做到不动点

> **触发**：修完 D1+D2 后复量，`sz.300760` 日线仍只有 **3 段 / 最长 127 笔**。
> 这一条**连用户都没报**，是补上 §6.1 第 2 条规则（按「状态」而不是「数量」扩样本）
> 之后，在全史指数 + 晚上市票上翻出来的。

**原文基准（第67课，一手，逐字）**：

> 关于特征序列，把每一元素看成是一K线，那么，如同一般K线图中找分型的方法，也存在所谓的包含关系，也可以对此进行非包含处理。**经过非包含处理的特征序列，成为标准特征序列。**以后没有特别说明，特征序列都是指标准特征序列。
>
> 首先请先搞清楚特征序列，然后搞清楚**标准**特征序列，然后是标准特征序列的顶分型与底分型。

**代码缺陷**：`_merge_feature` 只做**单趟前向合并** —— 把新元素并入末元素之后就结束了，
合并出来的新元素**不再回头与前一元素比较**。合并会**放大**区间，放大后可能反过来包含
前一元素；而第65课明说包含关系「不符合传递律」，所以这个回头是必须的。
第79课**禅师自己**就是这么做的（第24段）：「34、56、78，其中前两者可以进行包含关系
处理，因此可以合并为36（指区间），所以78显然和12、36构成底分型」——先包含，再判分型；
第26段同理：「由于9-10是78的包含关系，所以可以认为线段二延伸到了10」。
第71课把这条道理讲透了：「但假设的转折点后的顶分型的元素，是可以应用包含关系的。……
同一类的东西，当然可以考察包含关系。」
评论区读者**今才觉艳**（2011-05-14）把它读成通则：「在分析特征序列包含关系的时候，
**要先把所有的特征序列先包含，然后再分段。而不是只处理最近的特征序列包含关系就可以**」
——**这是读者的读图笔记，不是禅师原话**，仅作佐证。

**后果不是「判据偏严」，是判据失效**。逐步追踪（`sz.300760` 日线，`_feature_seq(ss, 0, 1)`）：

```
std[7] ⊂ std[8]  ⇒  _is_fractal_at(std, 8, 1) 要求 393.502 > 405.576  ⇒  False
⇒ 全局最高点笔27 永远不在 candidates 里
⇒ candidates(0) == []  ⇒  best(0) == (0, None)
⇒ classify 只能从笔1 起段  ⇒  132 笔塌成 3 段，最长段 127 笔
```

**修复**（`round-019`，`optimizer/patches/round-019-D3-standard-feature-seq.patch`）：

### A.7 D5：左端起点 —— 原文空白项下的工程口径（argmax）

> **触发**：D3 修完，`sz.399001` 全史已有 65 段，但用户报告的症状**依然在**：

**这是原文空白项，不存在「照原文改」的选项。** 第67/71/77/78 课都只宣示划分**唯一**：

本地 `../chanlun108/回复/` 里第 67/71/78 课的评论区，缠师本人**都没有回复**过这类问题。

#### A.8.1 结构性证明：算法层不认识「代码」

在跑数据之前，先看代码本身能不能针对某只标的：

- `src/chanlun/chan/` 全部模块中，`code` 只出现在 `engine.py`，且只用于**报错信息**与给
  `Snapshot` 打标签（`code=self.code`），**没有一处分支**。
- 所有判据函数的入参只有数字序列：`_has_gap(a, b)`、`_merge_feature(feats, direction)`、
  `_is_fractal_at(std, k, direction)`、`_first_three_overlap(strokes, start)`……

- `segment.py` 中出现的 `sz.399001` / `600180` / `sz.300760` / `603777` 等代码**全在注释里**，
  是证据引用，不是逻辑。

也就是说，**代码在结构上不可能知道自己在算哪只股票**。这不是「我声称它通用」，是类型签名
层面的事实。

#### A.8.4 独立检验：窗口一致性，以及差异究竟来自哪里

用**与「段数多少」无关**的独立判据复核：同一只股票用不同起点截断（2018/2020/2022-01-01），
重叠区间内的线段是否与全历史一致。各取 120 只做对照。

| 分组 | 修复前 | 修复后 |
|---|---|---|
| 变好组（最长段变短的 3104 只） | 3117/3436 = **90.7%** | 4875/5102 = **95.6%** ↑ |
| 变差组（最长段变长的 457 只） | 4271/4492 = **95.1%** | 4332/4661 = **92.9%** ↓ |

变差组确实**略微更不稳**，这是真实信号，不掩饰。但进一步定位差异出现在线段序列的哪个位置：

| 不一致落在 | 修复前 | 修复后 |
|---|---|---|
| 第 0 段（最左） | 143/221 = 64.7% | 151/329 = 45.9% |
| 第 0~2 段 | 220/221 = **99.5%** | 301/329 = 91.5% |
| 第 3 段及以后 | 1 处 | 28 处 |

关键的一步：把这 28 处「深入到第 3 段及以后」的标的单独拿出来看，它们的**左端是否也不一致**——
结果是 **18/18 = 100% 都伴随左端不一致**，「左端一致、仅内部不一致」的有 **0 只**。

**结论**：两版的**内部判据都不存在独立的不稳定**。修复后差异传播得更远，是因为左端起点
（§A.7 的**原文空白项**）选得不同，而线段是从起点向前递推划分的，起点一变，其后整条链都会平移。
变差组那 2.2 个百分点的代价，**全部记在左端这一个自由度上，没有一分记在内部判据上**。

#### A.8.5 本节的可复用结论

1. **「改了通用规则还是针对单只」这个问题，必须用全市场对照回答**，不能用「我改的是通用函数」
   这类自陈回答——自陈无法排除隐蔽的特例分支。
2. **先做结构性证明**（签名层面能不能认识标的身份），**再做统计对照**（全市场逐只）。两者都做，
   才叫证明了通用性。
3. **单指标（最长段笔数）是噪声很大的代理**：`sh.600012` 修复前也有一段 49 笔的长段，
   修复后最长段从 49 变 53，指标「变差」但两版都不健康。**必须同时看「修复前本来多病」**，
   否则会把「病的位置挪了几笔」误报成「新增了病」。
4. **变差的方向也要给出独立判据**（这里是窗口一致性），并**定位差异的物理位置**
   （左端 vs 内部）。否则「有 457 只变差」这种数字既不能证实也不能证伪任何东西。

### 2.1 包含处理 ✅ 严格遵守

**原文（第65课，一手）** <https://chanlun108.cn/chanzhongshuochan108ke/65.html>

> 1、用[di,gi]记号第i根K线的最低和最高构成的区间，当向上时，顺次n个包含关系的K线组，等价于[maxdi,maxgi]的区间对应的K线……向下时，顺次n个包含关系的K线组，等价于[mindi,mingi]的区间对应的K线。
>
> 2、……包含关系，不符合传递律……因此在K线包含关系的分析中，还要遵守**顺序原则**，就是先用第1、2根K线的包含关系确认新的K线，然后用新的K线去和第三根比，如果有包含关系，继续用包含关系的法则结合成新的K线，如果没有，就按正常K线去处理。
>
> 3、……假设，第n根K线满足第n根与第n+1根的包含关系，而第n根与第n-1根不是包含关系，那么**如果gn>=gn-1**，那么称第n-1、n、n+1根K线是向上的；**如果dn<=dn-1**，那么称第n-1、n、n+1根K线是向下的。

**代码**：`src/chanlun/chan/include.py`

| 原文要求 | 代码 | 判定 |

| 顺序原则（不满足传递律） | `include.py:63-74` 增量并回 `merged[-1]`，下一轮再与新 bar 比 | ✅ |
| 方向 `gn>=gn-1` | `include.py:59` `1 if merged[-1].high > merged[-2].high else -1` | ⚠️ **`>` vs `>=`** |

### 2.3 笔 ⚠️ 口径偏严（老笔 vs 新笔）

缠论有**两代**笔定义，必须分开：

#### 2.4.0 先立原文基准（第67课，一手，逐字）

> **特征序列定义**：用S代表向上的笔，X代表向下的笔……以向上笔开始的线段，可以用笔的序列表示：S1X1S2X2S3X3…SnXn。……定义：**序列X1X2…Xn成为以向上笔开始线段的特征序列**；序列S1S2…Sn成为以向下笔开始线段的特征序列。
>
> **标准特征序列**：关于特征序列，把每一元素看成是一K线，那么，**如同一般K线图中找分型的方法**，也存在所谓的包含关系，也可以对此进行非包含处理。经过非包含处理的特征序列，成为标准特征序列。
>
> **缺口**：特征序列两相邻元素间**没有重合区间**，称为该序列的一个缺口。
>
> **只考察哪一侧**：以向上笔开始的线段的特征序列，**只考察顶分型**；以向下笔开始的线段，只考察底分型。
>
> **第一种情况**：特征序列的顶分型中，第一和第二元素间**不存在**特征序列的缺口，那么该线段在该顶分型的**高点处**结束，该高点是该线段的终点；……
>
> **第二种情况**：特征序列的顶分型中，第一和第二元素间**存在**特征序列的缺口，如果**从该分型最高点开始的向下一笔开始的序列的特征序列出现底分型**，那么该线段在该顶分型的高点处结束，该高点是该线段的终点；……**强调，在第二种情况下，后一特征序列不一定封闭前一特征序列相应的缺口，而且，第二个序列中的分型，不分第一二种情况，只要有分型就可以。**
>
> **唯一性**：上面两种情况，就给出**所有**线段划分的标准。显然，出现特征序列的分型，是线段结束的前提条件。……显然，按照这个划分，一切同一级别图上的走势都可以**唯一地**划分为线段的连接……这是基础的基础，请务必搞清楚，否则肯定学不好。

**先说结论：`end_idx = std[k][2] - 1` 是对的** ✅。原文说线段在「该顶分型的**高点**处」结束；顶分型的高点在其**中间元素**上，而中间元素是向下笔，其高点 = 该向下笔的起点 = 它前面那根向上笔的终点 → `std[k][2] - 1` 正是这根向上笔。代码与原文逐字对应。

**「只考察顶分型」也对了** ✅：`segment.py:181` `kind = "top" if direction == 1 else "bottom"`，`_is_fractal_at` 按方向分别判顶/底 ✅。
