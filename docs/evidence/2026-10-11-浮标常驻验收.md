# 右下角浮标变成「这一只这一周期」的常驻数据状态：验收（2026-10-11，D-50）

## 0. 一句话

用户 2026-10-11 说：

> 不是吧？我看现在这个也没有那个手动拉取的那个按钮呀。就比如说是 ST洲际的 30 分钟 K 线，
> 我点进去之后，它也没有自动拉取，也没有手动拉取的按钮，这肯定不对吧？

**这句话是对的，而且两句都对得上代码。**

- **「没有手动拉取的按钮」——完全成立。** 全站唯一的手动入口是 `app.js:229` 的
  404 分支（`label: "同步这个周期"`），也就是说：**只有"本地一条数据都没有"时才出现按钮**。
  有数据但落后的情形（ST洲际 30 分当时就是）连按钮都没有，浮标也只是一行
  `12px` 的灰字。
- **「没有自动拉取」——在正确的点击流程里不成立，但用户的感受有四个叠加成因。**
  D-49 已经实测过：`?code=002309` 点进 30 分，浮标会显示
  `已补到 2026-10-09 15:00`，`POST /api/sync` 9→10。可是：
  1. 有数据但落后时浮标**不可点**，只有一行小字；
  2. **已最新时浮标一个字都不显示**（`maybeAutoSync` 直接 `return`）；
  3. 一次真实同步实测 **2.0 s – 28.5 s**（baostock 偶发 `[Errno 60] Operation timed out`
     会重试），而浮标 `12px`、补完 **4 秒后自己消失** —— 低头看一眼就错过了；
  4. 静态文件**没有任何 `Cache-Control`**，改完前端不硬刷新可能还在跑旧 JS。

D-50 把浮标改成**常驻的「这一只这一周期」数据状态**，落后时它自己长出一个真
`<button>`；顺手给静态文件加 `cache-control: no-cache`。

**七态在真浏览器里逐态核过**（§3.2）。其中 `done`、`已自动补过一次`、`blocked` 三态
在这次验收窗口里**没有天然活样本**（原因见 §3.2），是用变异逼出来的，逐条如实标注。

## 3. 验收（可失败的测量）

### 3.1 布局零位移：五种配置的 rect 逐字节相同

浮标是**绝对定位**（`.stage` 是 flex 列，占流的子元素会把 `.chart` 挤矮），
而"顶栏恒定 2 行 / 窄屏不跳高度"是既有硬约束。所以硬要求是：
**浮标不管显示什么、显示多长，`#chart` / `.stage` / `#stamp` / `#stamp-detail`
的 rect 和 `body` 的网格行必须一模一样。**

探针直接把浮标摆成五种配置逐一量（`/tmp/probe_chip_layout.js`，视口 1600×1000）：

| 配置 | 浮标自身 rect `[l,t,w,h]` | `#chart` | `.stage` | `#stamp` | `#stamp-detail` | `body` 网格行 | body 子元素 |
|---|---|---|---|---|---|---|---|
| A 隐藏 | `[0,0,0,0]` | `[310,228,954,684]` | `[310,153,954,759]` | `[1038,21,542,34]` | `[0,77,1600,42]` | `77px 42px 34px 760px` | 7 |
| B `fresh` | `[1090,868,156,32]` | 同上 | 同上 | 同上 | 同上 | 同上 | 7 |
| C `stale` + 按钮 | `[826,848,420,52]` | 同上 | 同上 | 同上 | 同上 | 同上 | 7 |
| D `failed` + 按钮 | `[826,848,420,52]` | 同上 | 同上 | 同上 | 同上 | 同上 | 7 |
| E `blocked`（70 字 hint） | `[826,832,420,68]` | 同上 | 同上 | 同上 | 同上 | 同上 | 7 |
| F 整块 `remove()` | `null` | 同上 | 同上 | 同上 | 同上 | 同上 | 7 |

- 六行的 `#chart` / `.stage` / `#stamp` / `#stamp-detail` / 网格行 **逐字相同**，
  `bodyKids` 恒为 `7` ⇒ **零位移成立**。
- 浮标宽度封顶 `420`（`max-width: min(420px, 60%)`），`blocked` 那 70 字折成 3 行
  也只长高、不撑宽。
- 锚点：`.stage` 右边缘 `310+954 = 1264`，浮标右边缘 `826+420 = 1246 = 1264-18` ⇒
  `right: 18px`；`.stage` 下边缘 `153+759 = 912`，浮标下边缘 `900 = 912-12` ⇒
  `bottom: 12px`。**浮标挂在 `.stage` 上，不是挂在视口上。**

> **为什么不做成顶栏按钮**：顶栏那一格必须恒定 2 行，加按钮会挤 `.period`（`flex:0 1 auto`），
> 实测按钮 36→56px、顶栏 93→110px。见 D-49 §4.6。

### 3.3 请求计数汇总

`POST /api/sync` 是 uvicorn 访问日志里的行，**整场验收唯一不含主观判断的数字**。

| 场景 | URL | 增量 | 说明 |
|---|---|---|---|
| 已最新 | `600000&day` | **+0** | 一个请求都不发 |
| 落后（不点） | `300114&day` | **+1** | 自动补一次 |
| 落后（点「点这里补」） | `300114&day` | **+2** | 自动 1 + 手动 1 |
| 补失败（自动） | `300114&day` | **+1** | 失败也要发一次才知道失败 |
| 补失败（点「重试」） | `300114&day` | **+2** | 自动 1 + 重试 1 |
| `done`（变异） | `300114&day` | **+1** | 只发一次 |
| 404 让位 | `000033&period=30` | **+1** | 浮标不说话，自动仍发 |
| `blocked`（变异） | `600000&day` | **+0** | 补不了就不发，对 |

会话内去重（同一只票只自动试一次）由 `autoTried` 承担，D-49 §3.4 已验，D-50 未改。

### 3.4 静态文件缓存头：前后对照

**修之前**（Task 3 Step 1，TestClient 打在未修改的 `app.py` 上）：

```
/static/app.js  200  cache-control= None  etag= True
/               200  cache-control= None  etag= True
```

**修之后**（活体 `curl`，服务已重启）：

```bash
$ curl -s -o /dev/null -D - "http://127.0.0.1:8888/static/app.js?cb=$RANDOM"
HTTP/1.1 200 OK
content-length: 108771
etag: "c9770de2e8cdc6bba5a5f644bb73a2bd"
cache-control: no-cache

$ # 带 If-None-Match（304 里那个头必须还在）
HTTP/1.1 304 Not Modified
cache-control: no-cache

$ curl -s -o /dev/null -D - "http://127.0.0.1:8888/?cb=$RANDOM"
HTTP/1.1 200 OK
cache-control: no-cache
content-length: 10546

$ # 首页带 If-None-Match：**仍然 200，永远不会 304**
HTTP/1.1 200 OK
content-length: 10546
```

三条要点，都要说清：

1. **`no-cache` 不是"不缓存"**，是"每次都要回源确认"。`etag` 还在，没改的文件
   依然走 **304**，带宽没浪费 —— 只是**改了的一定立刻生效**。
2. **304 里 `cache-control` 保住了**，这件事不显然：Starlette 的
   `NotModifiedResponse.NOT_MODIFIED_HEADERS` 只白名单转发几个头，
   `cache-control` 在白名单里。而且头必须写在**覆写的 `get_response` 里**（`super()`
   返回之后），写在 `FileResponse(headers=…)` 里会被那张白名单**滤掉**。
3. **首页 `/` 根本没有 304 通路**：它由 `@app.get("/")` 直接返回 `FileResponse`，
   绕开了 `StaticFiles.is_not_modified`。代价是每次开页面重发 10.5 KB，
   换来的是"改了 `index.html` 立刻生效"。这个取舍写进了 `app.py` 的注释。
   顺带：`HEAD /` 是 **405**（FastAPI 的 `@app.get` 不像 Starlette 的 `Route` 那样
   自动补 HEAD），`HEAD /static/app.js` 是 **200**。这是既有不对称，不是 D-50 引入的。

**"修之前"这个数现在不能靠原样重跑得到**（代码已经修好了）。它的可失败复现方式是
变异 **M8**（把 `resp.headers["cache-control"] = "no-cache"` 删掉）：
`tests/web/test_static_cache.py` 立刻 **2 failed, 1 passed**。见 §4.4。

## 4. 实施中发现并修掉的缺陷

### 4.1 `skipped` 从「失败」改成「落后可点」——旧文案自相矛盾

D-49 的 `finishAutoSync` 把 `status.state === "skipped"` 落进 `chipState("failed", …)`，
于是屏幕上出现：

```
补数据没成功：本地记录已是最新，文件里还没有新数据
```

前半句说没成功、后半句说已是最新 —— **同一行里自相矛盾**。
成因是后端 `sync_one` 的水位短路（`start_for` 返回晚于 `end` 的下一交易日 ⇒ 没联网
就 `skipped`），前端却把它当失败。

D-50 改成 `chipState("stale", job, "本地记录已是最新，文件里还没有新数据")`，
即"落后可点"态：说明为什么没补到，并把按钮留着让用户自己再试。
**这一态现在幂等**，所以它是本次验收最好用的样本（§3.2.2）。

### 4.2 `syncing` 文案里的 `?`

D-49 的 404 分支传 `local: null`，`syncing` 文案直接插值，屏幕上印出
`本地截至 ?，最新交易日 2026-10-09…`（`/tmp/probe_404.js` 实测原文，§3.2.3）。
D-50 改成 `job.local || "无本地数据"`。

### 4.3 注释里把 `sync_hint` 的长度写错了（84 → 实测 70）

`styles.css` 的浮标注释写的是「`sync_hint` 实测 **84** 字」。这次逐字量了活体 API：

$ len(detail)    = 100

而且 `git show HEAD:chanlun/src/chanlun/web/api.py` 里那段理由**逐字未变**（都在 `:987`），
所以不是文本变了，是当初数错了。已改成 **70**。

（这条结论本身也说明注释里的数字必须有可重跑的命令撑着 —— 它当时没有任何测试拦。）
