# 行情结构不可能的行（2026-10-06，F-2 / D-46）

## 0. 一句话

`normalize` 原先只查「非正价格」（`(out[price_cols] <= 0).any(axis=1)`），
不查「结构不可能」的行。现在追加两档（`src/chanlun/data/types.py:64-99`）：
**倒挂（`high < low`）⇒ 剔除**（`:81-88`），
**越界（`open` 或 `close` 出了 `[low, high]`）⇒ 保留、只警告**（`:90-99`）。
判据是**严格小于**，一字板（`high == low`）不受影响。

全库 5613 个 parquet / **9,119,671 行**，存量命中 **倒挂 2 行**、**越界 62 行**。
这 2 行**不是 inert**：`sh.000001` 日线那根在 `merge_bars` 之后确实变成一根
`high=1135.61 < low=1152.69` 的合并K线；`us.dji` 日线那根没有变成倒挂的合并K线，
但剔除它让**分型 2026 → 2024**。**是真实但极小的行为变更**，不是 no-op。

## 3. 倒挂行不是 inert

探针的第二段做了**两个口径**的对比。口径 A 证明机制，口径 B 证明影响半径。

- **口径 A（机制层）**：`chan/include.py::merge_bars` 直读 `high`/`low`，
  **不经过** `normalize` ⇒ 「倒挂行会变成一根 `high < low` 的合并K线」
  在修复前后都能实测。
- **口径 B（引擎层）**：`ChanEngine.full()` 的入口就是 `normalize`，
  修复之后**没法**再把含倒挂行的帧喂进引擎（那条路正是被本次修复关掉的）。
  所以修复前的帧按「修复后帧 + 倒挂行按 `ts` 插回」重建，再直接调
  `ChanEngine._compute()` 绕过 `normalize` 重算。

  重建的依据：**修复前的 `normalize` 只有「≤0 剔除 + `drop_duplicates` + 排序」
  三步**，而倒挂行既不是 ≤0、`ts` 也不重复 ⇒ 它必然活过那三步。
  探针在重建后断言两边行数正好差「倒挂行数」，差得不对就 `SystemExit`
  —— 这一步是防「重建公式悄悄失效」的，不是装饰。

```console
=== 倒挂行对结构的影响（证明这 2 行不是 inert）===

口径 A（机制层）：`chan/include.py::merge_bars` 直读 high/low，**不经过**
  normalize**，所以「倒挂行会变成一根 high<low 的合并K线」在修复前后都能实测。
口径 B（引擎层）：`ChanEngine.full()` 入口就是 `normalize`，修复之后那条路

  口径 A  merge_bars(磁盘原样)   合并K线  4562 / 其中 high<low 0 根

```

**读法（这一段是本文档最要紧的部分）**：

- **`sh.000001` 日线**：倒挂行**真的**变成了一根 `high < low` 的合并K线
  （`idx=333`，`ts=1992-06-16`，`high=1135.61 < low=1152.69`）。
  剔除它之后合并K线总数**没变**（都是 7004）—— 少了一行原始K线，但包含关系
  随之改变，另一处的合并结果不同，**净数相抵**。分型 / 笔 / 线段 / 中枢
  **逐项不变**。
- **`us.dji` 日线**：那根倒挂行**没有**变成倒挂的合并K线（被左邻吸收后出来的
  是合法区间），口径 A 两行都是 `high<low 0 根`。**但剔除它仍然改变了结果**：
  **分型 2026 → 2024（−2）**，合并K线 / 笔 / 线段 / 中枢不变。

⇒ **两行都不是 inert，但爆炸半径极小**：没有任何一只票的**笔 / 线段 / 中枢**
发生变化。这既不是 no-op（有变化），也不是 `inconclusive`
（逐项相同才是）—— 按 `AGENTS.md` §5 证据质量规则，如实记成
**「真实但极小的行为变更」**。

> **这条结论和最初那份建议书的预期不一致。** 建议书 §F-2 的验收标准第 2 条写的是
> 「用真实库跑一次全量 `normalize` 幂等检查（读所有 parquet → normalize →
> 行数不变），确认没有误伤存量数据」。实测**行数确实会变**（倒挂 2 行被剔除），
> 而且其中 1 行真的改变了分型数。所以本文档不写「无影响 / 无变化」，
> 写的是逐票量出来的影响半径。

| ① | `test_normalize_drops_upside_down_bars` | 倒挂行被剔除，警告**点名 `ts`** | **红** |
| ② | `test_normalize_does_not_touch_a_limit_up_bar` | **一字板（`high == low`）不被误伤** —— 钉死「严格小于」 | 绿 |
| ③ | `test_normalize_keeps_out_of_range_bars_with_warning` | 越界行**保留**，警告里写明「仅观测，不剔除」 | **红** |
| ④ | `test_upside_down_bar_cannot_reach_the_merged_sequence` | 注入一根 `high=0.01, low=1e9` 的倒挂行后，`ChanEngine.full()` 的 `snap.merged` 里**不许出现 `high < low`**，且结果必须与「把这根直接删掉」逐项相同 | **红** |

修复前：`3 failed, 1 passed in 0.09s`（② 必须是绿的 —— 它钉的是「不许误伤一字板」）。
修复后：`4 passed in 0.38s`。

**第 ④ 条的构造为什么是确定的**：`high=0.01, low=1e9` 在**两个**包含方向下
（`max/max` 向上吸收、`min/min` 向下吸收）都必然产出 `high < low`。
修复前它失败时打印出的正是机制本身：

```
AssertionError: 合并K线序列里出现了空区间（high < low）
assert [MergedBar(idx=29, ts='2024-02-05', start_ts='2024-02-02',
                  high=0.01, low=9.5, direction=-1, src_start=29, src_end=32)] == []
tests/data/test_normalize_structure.py:141
```

**顺带修了两个数据源测试的探针取值**（不改判据，但必须同批做）：

- `tests/data/test_sina_source.py:57-72`、`tests/data/test_tencent_source.py:73-91`
  原本拿 `high < low` 当「四值互异」的探针来钉字段映射
  （sina `o=1.0, h=3.0, low=4.0, c=2.0`；tencent 原始行 `[ts, 1, 2, 3, 4, 5]`）。
  新判据会让整个帧被剔空 ⇒ `df.iloc[0]` 直接
  `IndexError: single positional indexer is out-of-bounds`。
- 改成 `low 1 ≤ open 2 ≤ close 3 ≤ high 4` —— **仍四值互异、逐列断言一字未动**，
  测的仍然是字段映射。**错位读法照样被测出来**：按 tencent 的
  `open,high,low,close` 顺序取这四位数，拿到的是 `high=3 < low=4`。
- **这两条不是「顺手改测试」**：不改的话它们测的就不再是字段映射了。
  教训记在这里 —— **任何 `normalize` 新判据都要回头核对这两个文件**，
  因为它们的探针是**故意**造成结构不可能的。
