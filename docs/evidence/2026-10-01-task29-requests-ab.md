## 2. 周K / 月K：由本地日线聚合

### 2.1 不落库、按自然周/自然月分组

`data/week`、`data/month` **不存在，也不该存在**：

```
data/day: True    data/week: False    data/month: False    data/30: True    data/5: True
```

分组按自然周（ISO）/自然月，不是「每 5 根 / 每 20 根」—— 节假日少几天，按根数切会把
上一周的最后一天并进来。戳 = 该周期**最后一个交易日**。指数日线 8736 根聚合出：

| 周期 | 根数 | 首根 |
| --- | --- | --- |
| 日线 | 8736 | 1990-12-19 |
| 周线 | 1817 | 1990-12-21 |
| 月线 | 430 | 1990-12-31 |

真机 DOM（周线）：

```
sh.000001 上证指数 · 周线 · 截至 2026-09-30
线段 3（确认 2 / 未确认 1） · 中枢 1 · 买卖点 1
全史 9 段 / 1 中枢 / 1 买卖点（这里只画与窗口相交的部分）
周线由日线聚合 · 趋势按 [ZD,ZG] 口径（…）
```

月线同理，只把「周线」换成「月线」。**周/月不是分钟周期**：`_is_minute_period`
从 `period != "day"` 改成「非派生且非日线」，否则周/月会被 F5 的规矩圈进自选池范围。

### 2.2 「先复权后聚合」是硬顺序，有量具钉住

后复权是把**每一天**的价格各乘一个因子，而周K的开盘价取的是那一周**第一天**的价格。
先把日线聚成周线、再整根乘最后一个交易日的因子，除权落在周中间时开盘价就错了。

新用例 `tests/web/test_api_periods_watchlist.py::test_week_bars_are_adjusted_day_by_day_before_aggregation`
造了一段「周三翻倍」的样本（周一 `k=1.0`、周三起 `k=2.0`）：

| 顺序 | 周K 开盘 | 周K 最低 | 判据 |
| --- | --- | --- | --- |
| 读日线 → **按日复权** → 聚合（主干） | **10.0** | **9.5** | 通过 |
| 聚合 → 整根乘周五因子（错的） | 20.0 | 19.0 | 失败 |

变异验证：把 `api.py::_period_frame` 里那两行对调后单独跑该用例 →
`assert 20.0 == 10.0 ± 1.0e-05` **1 failed**；换回来 → **15 passed**。
（`git status --porcelain -- src` 复原后为空，`api.py` 逐字回到主干。）

### 2.3 「最后一根没走完」要说出来 —— 但今天这一周**是走完的**

`partial` 的判据是 `periods.is_complete(last_ts, period, cal)`：
`cal.last_trading_day(period_end(day, period)) == day`，即**这个周期后面还有没有交易日**，
用的是真实日历，不是「周期末日到了没有」。

- 样本日线到 `2024-12-31`（周二）：那一周还差两天 → `partial=true`（有常驻用例钉住）。
- 今天（2026-10-01）上证最后一天是 `2026-09-30`（周三），第 40 周是 09-28→10-04，
  但 **10-01/10-02 是国庆休市**、10-03/04 是周末 → 这一周不可能再出新数据 →
  `partial=false`。月线同理（09-30 就是 9 月最后一个交易日）→ `partial=false`。

所以真机 DOM 今天**看不到**「（最后一根未走完）」这行字，这是对的、不是漏标：
标出来的是「还会变的根」，而这一周已经定型。接口实测：

```
$ curl -s "http://127.0.0.1:8888/api/structure?code=sh.000001&period=week" | ...
  {'derived': True,  'base_period': 'day', 'partial': False, 'as_of': '2026-09-30', 'bars_total': 1817}
  {'derived': True,  'base_period': 'day', 'partial': False, 'as_of': '2026-09-30', 'bars_total': 430}
  {'derived': False, 'base_period': 'day', 'partial': None,  'as_of': '2026-09-30', 'bars_total': 8736}
```

日线 `partial=None` 是**故意**的：日线本来就是落库周期，没有「走没走完」这回事；
日历拿不到时也返回 `None`（不假装走完了）。

## 3. 默认自选池 = 七个大盘指数

`meta.DEFAULT_WATCHLIST` 换成七个指数，原来那 4 只股票自选**删掉**（用户：「去除其他的」）。
一键种子 `python -m chanlun seed-watchlist` 清空重来，只放那七个。实测（本地库现状）：

| # | 代码 | 名称 | 根数 | 区间 | `sync_state.adjust` |
| --- | --- | --- | --- | --- | --- |
| 0 | `sh.000001` | 上证指数 | 8736 | 1990-12-19 → 2026-09-30 | `'3'`（不复权） |
| 1 | `399001` | 深证成指 | 8653 | 1991-04-03 → 2026-09-30 | `'3'` |
| 2 | `399006` | 创业板指 | 3968 | 2010-06-01 → 2026-09-30 | `'3'` |
| 3 | `sh.000300` | 沪深300 | 5282 | 2005-01-04 → 2026-09-30 | `'3'` |
| 4 | `sh.000016` | 上证50 | 5525 | 2004-01-02 → 2026-09-30 | `'3'` |
| 5 | `sh.000905` | 中证500 | 5282 | 2005-01-04 → 2026-09-30 | `'3'` |
| 6 | `sh.000688` | 科创50 | 1637 | 2019-12-31 → 2026-09-30 | `'3'` |

种子跑完自报：`指数日线：成功 7 失败 0 跳过 0（共 7 只）`。

**指数一律不复权**（`markets.is_index` → `adjustflag=3`）：指数没有除权，若沿用
`bs_adjust="2"`，`sync_state.adjust` 会替指数声称「前复权」——那是假的。
代码口径沿用 `markets.store_key` 的既有约定：沪市带 `sh.`、深市 `399xxx` **裸码**，
种子行与用户手输的行因此是同一个键。

### 3.1 科创50 的两级兜底：baostock 空数据 → 本地通达信整包

`sh.000688` 走 baostock 返回 0 行（已重登重试），于是落回本地通达信整包。这里有个
**真会踩的坑**：`markets.store_key("sh.000688")` 是 `sh.000688`（带前缀），而
`to_bs_code("sh.000688")` 也是 `sh.000688`；但 `store_key("sh.600000")` 是**裸码**
`600000`。拿 store key 去拼文件名会拼出 `sh600000.day`（不存在），于是号段检查
被静默跳过。所以文件路径一律由 `to_bs_code(code).partition(".")` 拼。

同一个数字在两个市场不是同一只票，实测：

```
data/tdx_raw/sh/lday/sh000688.day: 1637 根 2019-12-31 → 2026-09-30 close=1530.01   ← 科创50
data/tdx_raw/sz/lday/sz000688.day: 5433 根 1997-01-20 → 2026-09-30 close=24.24     ← 另一只
```

两条常驻用例钉住这段逻辑（`tests/test_cli.py`）：一条让 `fetch_bars` 返回 0 行、
断言兜底后 `store.exists("sh.000688","day")` 且 `close == 1015.0`；一条拿
`sh.600000`（股票号段）调 `_tdx_index_frame`，断言 `df is None` 且理由里含
**「不是指数」**——不许拿一只股票去冒充指数。

## 4. 自选池增删改查（真机跑，不是只跑单测）

`watchlist` 表加 `sort_order`，老库一次性 `ALTER TABLE` + 回填。真机对着
`127.0.0.1:8888` 跑（服务器 `bash-2946`，启动于 `3aad8e7` 之后）：

**改（排序）** —— `PATCH /api/watchlist {code, delta}`：

```
before            ['sh.000001','399001','399006','sh.000300','sh.000016','sh.000905','sh.000688']
399001 delta=-1   ['399001','sh.000001','399006', …]        ← 真的换了位置，且落了库
399001 delta=+1   ['sh.000001','399001','399006', …]        ← 移回来，顺序复原
delta=0           HTTP 400
code=999999       HTTP 404
sh.000001 delta=-1  {'ok': true, …顺序不变}                  ← 首行上移是空操作，不是报错
```

**增 / 删** —— `POST` 只给代码，名字自动补上；`DELETE` 移除：

```
POST   {"code":"600030"} → {'ok': true, 'code': '600030'}
       … 池尾出现 ('600030', '中信证券')      ← 名字从品种表兜底，不用手输
DELETE ?code=600030      → {'ok': true, 'code': '600030'}
       … 池子回到 7 只指数，顺序不变
```

页面上：行尾悬停浮出 ▲▼（首尾对应方向**置灰** —— 后端在边界是空操作，界面不能做出
「点了会动」的样子），`×` 仍是移出；加票是左上角「代码 / 名称 + 加入」。左侧栏底部写清
「默认是七个大盘指数；日线在本地，周线/月线由日线聚合。缺数据的票会标出来，↑↓ 调顺序。」
